#!/bin/bash
# =============================================================================
# Cycle 51 -- THE UNCLIPPED FAMILY CONTROL.  Runs on cluster_a.  18 jobs.  Tag `uc5-*`.
#
# OPEN QUESTION IT ANSWERS, and it is a threat to the campaign's headline that was
# invisible until this tick's instrument correction.
#
#   CORRECTIONS 59 promoted the headline from one architecture to four:
#     "At the adapted equilibrium, per-weight meta-gradients carry between 16% and 55%
#      of the independent information their count implies -- N_eff/m = 0.163 (R10) /
#      0.481 (R18) / 0.552 (R34) / 0.305 (CIFAR-100)."
#   Verified from the probes this tick: 0.1632 / 0.4808 / 0.5517 / 0.3047.  The prose
#   matches the data.
#
#   FINDINGS 51.1 showed that the BETA_CLIP occupancy this campaign has been quoting was
#   read from the PER-TENSOR `beta[]` list -- one MEAN per tensor -- while the clamp is
#   applied PER COORDINATE.  Re-read at the resolution the clamp operates at, the free
#   family arms the headline rests on look completely different (FINDINGS 51.3):
#
#     weightwise, ff5/fr5      %rec any coord at LO   at HI    Q4 at LO   Q4 at HI
#       r10                            18.5            52.0       74.0      100.0
#       c100                           18.7            50.9       74.7      100.0
#       r18                             8.1             8.2       32.4       28.5
#       r34                             0.2             0.0        0.8        0.0
#     (the per-TENSOR column reads 0.00% for ALL of these -- that is the whole problem)
#
#   The steady half is records 1000-2000, so it CONTAINS all of Q4.  Two of the four
#   headline numbers -- 0.163 (R10) and 0.305 (CIFAR-100), i.e. the two that set the
#   LOW end of the quoted "16% to 55%" range -- were measured in arms whose ceiling is
#   occupied on 100% of last-quarter records.  Nobody has checked whether the box sets
#   the number.  This batch checks it.
#
#   SECOND QUESTION, from the same table.  CORRECTIONS 60 records a x2.7-2.9 rebound in
#   free rho_w at k=1 in Q4, "with two mechanisms tested and BOTH FAIL".  Mechanism (i)
#   was clip saturation, and it was rejected on "0.0% of TENSOR betas at either guard".
#   At coordinate resolution the four families separate PERFECTLY:
#       rebound YES:  r10 (Q4 ceiling 100.0%),  c100 (100.0%)
#       rebound  no:  r18 (28.5%),              r34 (0.0%)
#   CORRECTIONS 60's own text said the honest status was "*unsupported*, not *excluded*";
#   CORRECTIONS 61(5) then wrote it up as "both fail".  61(5) was too strong and this
#   batch is the first actual test of (i).
#
# THE DESIGN.  One variable: the box.  BETA_CLIP -15:-2.3026 -> **-30:0.0**, i.e. both
# walls pushed out to where FINDINGS 51.2's measured drift rates say neither can be
# reached inside 2000 records.  Everything else is byte-matched to `c49_free_family_ladder.sh`
# (SGDm/Lion, ms=1e-3, alpha0=1e-3, 20 epochs, AUGMENT=1, seeds 0-1, same rungs).
#
#   WHY BOTH WALLS AND NOT ONE.  Cycle 50's wc5 moved one wall and the batch came back
#   uninterpretable because the OTHER wall was the dominant one.  In r10 and c100 BOTH
#   walls are occupied in Q4 (74% low, 100% high), so moving one would repeat the exact
#   mistake this tick is correcting.  The floor move is separately measured to be nearly
#   inert at R18 (N_eff/m +0.038, plateau +0.027 pp, FINDINGS 51.4), so the pair is not
#   two unknown variables -- it is one known-small one and one large one.
#
#   FAMILIES.  r10 and c100 are the saturated pair the headline is at risk in.  **r34 is
#   the built-in NULL**: its weightwise ceiling occupancy is 0.0% and its floor 0.2%, so
#   the box is provably not touching it and widening it must change nothing.  That null
#   costs 6 of the 18 jobs and is what makes the other 12 quotable.
#   r18 is NOT included: `cl5-*` (submitted this tick on cluster_b) is already a three-point
#   ceiling ladder at exactly R18/CIFAR-10/ms=1e-3, and duplicating it would be waste.
#
# PRE-REGISTERED PREDICTIONS -- score the verdict against these, not against what lands.
#
#   (U0) VALIDITY GATE.
#        1. beta must MOVE: beta_true_max != beta_true_min on the last record, 18/18.
#        2. n_records == 2000 and weightwise n_tot must match the ff5 partner EXACTLY:
#           r10 4,903,242 / c100 11,220,132 / r34 21,282,122.  A mismatch voids everything.
#
#   (U0.3) **THE NULL, SCORED FIRST.**  r34 weightwise: N_eff/m within +-0.10 of 0.5517
#        and plateau within +-0.6 pp of 70.281.  If r34 weightwise MOVES, the widening
#        changed something other than the box and NOTHING in this batch is quotable.
#
#   (U0.4) **THE DOSE CHECK, ALSO BEFORE U1.**  In the new r10 and c100 weightwise arms,
#        the fraction of Q4 records with any coordinate at either guard must fall below
#        5% (from 100.0% at the ceiling, 74-75% at the floor).  If it does NOT fall, the
#        box is still saturating, and U1/U2 are **UNINTERPRETABLE rather than refuted** --
#        say exactly that.  This is the W2 lesson and it is being applied deliberately for
#        the second time in one tick, because ignoring it is what cost cycle 50 its batch.
#        PATCH_CLIPCOUNT (CORRECTIONS 63, applied to both accounts' HF.py this tick) makes
#        these the first runs to write n_at_lo / n_at_hi / n_beta, so the per-(record,
#        COORDINATE) denominator exists for the first time.  Report it ALONGSIDE the
#        per-record one, never instead of it (STANDING RULE 5).
#
#   (U1) THE PRIMARY TEST -- IS THE 4-FAMILY HEADLINE A BOX ARTEFACT?
#        N_eff/m, weightwise, VARIANCE instrument, STEADY half (the only quotable
#        combination, CORRECTIONS 55/59).  Controls, re-derived from the probes this tick:
#            r10  0.1632      c100  0.3047      r34  0.5517 (the null)
#        PASS: r10 and c100 both within +-0.10 absolute of their ff5 values.
#          --> The box does not set the number.  CORRECTIONS 59 stands as written and the
#              "16% to 55%" range needs no box caveat.
#        REFUTATION: either moves by more than 0.10.  The DIRECTIONAL prediction, stated
#          now so a confirmation cannot be fitted afterwards: unpinning should move
#          N_eff/m **UP**, because coordinates frozen against a common wall agree with each
#          other for a reason that has nothing to do with the meta-gradient.
#          --> Then the two numbers that set the LOW end of the published range are partly
#              the box, "16%" must be re-derived, and CORRECTIONS 59 needs a box column.
#        WHY +-0.10: 2.6x the measured floor sensitivity at R18 (0.038 for a 2.2x deeper
#        box, FINDINGS 51.4).  Same bar as `cl5`'s X1, deliberately.
#
#   (U2) THE REBOUND -- CLOSING OR RE-OPENING CORRECTIONS 60.
#        Control ratios, rho_w(Q4)/rho_w(Q3) at k=1 (FINDINGS 50.3): r10 x2.73, c100 x2.87,
#        r34 unchanged (the frozen control decays /1.9-2.0 in all four).
#        PREDICTION: with the box relieved the rebound DISAPPEARS -- ratio < 1.5 in both
#          r10 and c100 -- while r34 is unchanged.
#          --> CORRECTIONS 60's "unexplained" CLOSES; the mechanism is clip saturation, and
#              the reason it was missed is the per-tensor/per-coordinate resolution error.
#        REFUTATION: the ratio stays > 2.0 with U0.4 passed.
#          --> The FINDINGS 51.3 separation is a coincidence at n=4 families, and the effect
#              stays OPEN with mechanism (i) now genuinely excluded rather than untested.
#              That is a worse outcome than a confirmation but a better record than 61(5).
#
#   (U3) ACCURACY, reported regardless of U1/U2.  Plateau per arm against its ff5 partner
#        (r10-w 61.419, c100-w 26.846, r34-w 70.281; n=2 each).  wc5 measured the clip to be
#        accuracy-neutral at R18 (+0.027 pp over 6 matched cells).  If plateau moves by more
#        than 1 pp in any family, the box is doing real optimisation work there and every
#        accuracy comparison in that family needs a box caveat.
#
#   RESOLUTION, per CORRECTIONS 33, computed BEFORE submission.  rho_min is set by T and m
#   and does not depend on the box, so the ff5/fz3 floors carry over unchanged: weightwise
#   RESOLVES in 3 of 3 families; **r10 layerwise was named thin in advance in c49 (~0.5x)
#   and stays thin** -- a layerwise null there is a BOUND, never an absence.  n=2 per cell,
#   matching ff5 exactly, so the contrast is paired rather than powered.
#
# WHY cluster_a.  Account assignment is BY COMPARATOR (CORRECTIONS 46(6)).  Every number this
# batch is differenced against -- the whole `ff5-*` family ladder and its `fz3-*` frozen
# partners -- is on cluster_a.  `cl5-*` and its ml5/wc5 comparators are on cluster_b.
#
# STRUCTURAL CHECKS BEFORE USING ANY NUMBER (Rule 4)
#   1. U0, U0.3, U0.4 above, run not assumed, and IN THAT ORDER
#   2. python3 analysis/c51_wideclip.py --selftest   (26/26)  -- all three denominators
#   3. python3 analysis/probe5_window.py --selftest && analysis/neff_instrument.py --selftest
#   4. python3 analysis/probe5_time_ladder.py ../probes_uc5 ../probes_fz3   -- U2
#   5. Window scan on every arm.  Never quote a profile number without its window.
#
# USAGE
#   bash c51_unclipped_family.sh            # dry run: prints every sbatch line
#   bash c51_unclipped_family.sh --submit   # submits, ONLY if the guards below pass
# =============================================================================
set -u

WS=/cluster/account_a/metaopt                   # cluster_a
RUNNER=$WS/jobs/run_cifar.sh
HF=$WS/MetaOptimize/codes/Supervised_tasks/MetaOptimize/cifar10/Optimizers/HF.py
SAVE=$WS/runs/uc5
PARTS=gpu-short,gpu-l4-24g,gpu-2080ti-11g,gpu-mig-40g,gpu-a100-80g
USER_NAME=account_a
PEND_CAP=40
NJOBS=18
WIDE=-30:0.0                                       # both walls out; ff5 partner used -15:-2.3026
SUBMIT=0
[ "${1:-}" = "--submit" ] && SUBMIT=1

echo "=== c51 UNCLIPPED FAMILY control + PROBE5 (cluster_a) ==="
echo "    BETA_CLIP=$WIDE   (ff5 partner used -15:-2.3026);  r34 is the NULL"

if ! grep -q PATCH_PROBE5 "$HF" 2>/dev/null; then
  echo "GUARD FAIL: PATCH_PROBE5 not present in $HF"; exit 1
fi
if ! grep -q PATCH_PROBE5_FIX "$HF" 2>/dev/null; then
  echo "GUARD FAIL: PATCH_PROBE5_FIX not present -- unfixed patch crashes at record 500"; exit 1
fi
if ! grep -q PATCH_CLIPCOUNT "$HF" 2>/dev/null; then
  echo "GUARD FAIL: PATCH_CLIPCOUNT not present -- U0.4's per-coordinate denominator"; exit 1
fi
echo "guard 1: PATCH_PROBE5 + PATCH_PROBE5_FIX + PATCH_CLIPCOUNT present  OK"

python3 -c "import py_compile; py_compile.compile('$HF', doraise=True)" 2>/dev/null || {
  echo "GUARD FAIL: $HF does not compile"; exit 1; }
echo "guard 2: HF.py compiles  OK"

FS=$(sshare -U -u "$USER_NAME" -n -o FairShare 2>/dev/null | tr -d ' ' | head -1)
PEND=$(squeue -h -u "$USER_NAME" -t PENDING 2>/dev/null | wc -l | tr -d ' ')
echo "guard 3: FairShare=${FS:-unknown} (informational), pending=$PEND, adding $NJOBS"
if [ "$SUBMIT" = "1" ]; then
  [ "$((PEND + NJOBS))" -le "$PEND_CAP" ] || {
    echo "ABORT: $PEND pending + $NJOBS would exceed the $PEND_CAP cap"; exit 1; }
fi

mkdir -p "$SAVE"
N=0
sub () {   # sub <family> <nn-name> <dataset> <gran-token> <stepsize-groups> <seed>
  local fam=$1 nn=$2 ds=$3 gtok=$4 groups=$5 s=$6
  local RN="uc5-${fam}-${gtok}-s${s}"
  local PD="$SAVE/probe_${fam}_${gtok}_s${s}"
  N=$((N+1))
  local CMD=(sbatch --job-name="$RN" --partition="$PARTS" --time=03:50:00
    --export="ALL,AUGMENT=1,BETA_CLIP=$WIDE,PROBE=5,PROBE5=1,PROBE5_WRITE_EVERY=500,PROBE_DIR=$PD"
    "$RUNNER"
    --optimizer HF --alg-base SGDm --momentum-param-base 0.99 --weight-decay-base 0.1
    --alg-meta Lion --momentum-param-meta 0.99 --Lion-beta2-meta 0.9 --weight-decay-meta 0
    --dataset "$ds" --NN-name "$nn" --batch-size 100
    --max-time 999:00:00 --gamma 1 --meta-stepsize 1e-3 --alpha0 1e-3
    --num-epochs 20 --stepsize-groups "$groups" --seed "$s"
    --save-directory "$SAVE" --run-name "$RN")
  if [ "$SUBMIT" = "1" ]; then "${CMD[@]}" >/dev/null; else printf '%s\n' "${CMD[*]}"; fi
}

for s in 0 1; do
  # ResNet10 / CIFAR-10    -- REBOUND family, Q4 ceiling occupancy 100.0%
  sub r10  ResNet10 CIFAR10  lay  layerwise  "$s"
  sub r10  ResNet10 CIFAR10  node nodewise   "$s"
  sub r10  ResNet10 CIFAR10  w    weightwise "$s"
  # ResNet18 / CIFAR-100   -- REBOUND family, Q4 ceiling occupancy 100.0%
  sub c100 ResNet18 CIFAR100 lay  layerwise  "$s"
  sub c100 ResNet18 CIFAR100 node nodewise   "$s"
  sub c100 ResNet18 CIFAR100 w    weightwise "$s"
  # ResNet34 / CIFAR-10    -- THE NULL: ceiling 0.0%, floor 0.2%; must not move
  sub r34  ResNet34 CIFAR10  lay  layerwise  "$s"
  sub r34  ResNet34 CIFAR10  node nodewise   "$s"
  sub r34  ResNet34 CIFAR10  w    weightwise "$s"
done
echo "---- $N jobs ($( [ "$SUBMIT" = 1 ] && echo SUBMITTED || echo 'dry run, nothing submitted' )) ----"
echo "reduce with, IN THIS ORDER:"
echo "  1. python3 analysis/c51_wideclip.py                     # U0.3 null, U0.4 dose -- BOTH FIRST"
echo "  2. python3 analysis/neff_instrument.py ../probes_uc5    # U1 -- THE PRIMARY TEST"
echo "  3. python3 analysis/probe5_time_ladder.py ../probes_uc5 ../probes_fz3   # U2 rebound"
echo "  4. python3 analysis/probe5_window.py ../probes_uc5      # window scan, always"
