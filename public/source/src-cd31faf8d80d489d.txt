#!/bin/bash
# =============================================================================
# cWD5_wdladder.sh -- `cwd5`: ResNet18_c100 -- THE COUPLED WEIGHT-DECAY LADDER.
#   ONE SUBMISSION, 27 JOBS (9 arms x 3 seeds), 100 EPOCHS, SEEDS {146,147,148}, ResNet18_c100 / CIFAR-100,
#   PROBE=100, PROBE_TENSOR=1 ON EVERY ARM, --constraint=L4 ON EVERY JOB.  CORRECTIONS 281.
#
# ACCOUNT: account_b (cluster_b).  WORKSPACE: /cluster/account_b/metaopt.  Every guard and scancel line is filtered on `cwd5-`.
#
# REGISTERED SCORER: analysis/cWD5_wdladder_score.py (+ analysis/cwd5_design.py, and cwd1's analysis/cwd_design.py and
# analysis/cwd_common.py REUSED UNEDITED), committed and pushed BEFORE this batch is submitted (RULE 21).
#   DOCUMENTED INVOCATION:  python3 analysis/cWD5_wdladder_score.py <runsdir>
#
# WHY.  Every number in the mechanism line -- and every SCALAR cell of the audit's own granularity table -- sits at
# coupled base weight decay 0.1, ~200x the value a CIFAR ResNet is normally trained with.  cmo1 (264) fixed the two
# ENDPOINTS and nothing between: wd 0.1 collapses, wd 0 does not.  cwd5 measures the granularity gap at FOUR coupled
# weight decays with BOTH GRAINS IN BATCH at each, so every gap is a within-rung contrast.
#
# NO NEW HARNESS CODE.  `--weight-decay-base` is an EXISTING registered CLI float of train.py (default 0.1; cmo1 ran
# it at 0).  The ONE masked arm uses PATCH_DECAYMASK UNEDITED from cwd1's EXISTING isolated tree
# $WS/harness_cwd1/cifar10 (HF.py 94aedc33..., the bytes cwd3 and cwd4 ran on) with cwd1's EXISTING runner
# ($WS/jobs/run_cifar_cwd1.sh, 34a8c90e...).  The patch has never run at a weight decay other than 0.1, and no landed
# proof has ever exercised another `--weight-decay-base` value, so guard 4f requires cwd5's OWN bite log
# (bin/cWD5_realrun_bite.sbatch), which proves the ladder's premise and the new witness on the real GPU path.
#
# THE ARMS (no hold patch on any arm)
#   rung W1  wd 0.1    k01W1  scalar      | kLW1  layerwise        the campaign's anchor; replicates the mechanism cell
#   rung W2  wd 1e-2   k01W2  scalar      | kLW2  layerwise        + CARW2 scalar, DECAY_MASK = the three ctd1 carriers
#   rung W3  wd 1e-3   k01W3  scalar      | kLW3  layerwise
#   rung W4  wd 5e-4   k01W4  scalar      | kLW4  layerwise        the standard CIFAR SGD value
#
# RULE 20.  Every ARGS value is ONE shell token.  `weight-decay-base` and `stepsize-groups` VARY BY ARM, so they are
# NOT in the batch-wide DESIGN array: each composed line is checked against its OWN arm's pair, and the RULE 20 script
# passes `--vary weight-decay-base --vary stepsize-groups` to the batch-consistency half.  analysis/argsline_guard.py
# IS NOT EDITED.  A NON-STANDARD WEIGHT DECAY IS AN ARGS-VALUE DEVIATION: the 21 runs at wd != 0.1 go to
# results/CORPUS-EXCLUSIONS.tsv at landing as ARGS_WD_BASE rows (the kind exists since 263) and the 3 CARW2 runs also
# as DECAY_MASK rows (the kind exists since 269).  corpus_exclusions.py is NOT edited.
#
# HARDWARE (271.4(5), 273 bound (1)): every job carries --constraint=L4 and the partitions are gpu-short,gpu-l4-24g,
# so the whole batch runs on ONE accelerator type.  The scorer only DISCLOSES the device (G-HW); it never gates on it.
#
# COST.  cwd3 by sacct: 10.7111 GPU-h / 15 runs = 0.7141 per ResNet18_c100 run at this exact cell.  27 jobs ~= 19.3
#   GPU-h expected -- stated at the top of the range rather than rounded down.  HARD BOUND = WALL x 27 = 81 GPU-h.
#
# USAGE   bash bin/cWD5_wdladder.sh [--dry-run]   |   bash bin/cWD5_wdladder.sh --submit   (the ONLY submitting form)
# ENV     CWD5_REGISTERED_COMMIT=<40-hex sha>   on a host with no git repo, --submit requires it (271.6 F1: full sha)
# =============================================================================
