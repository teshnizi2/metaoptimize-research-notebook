# -----------------------------------------------------------------------------
# WHY THIS BATCH EXISTS.  THE NUMBER THAT MOTIVATES IT.
# -----------------------------------------------------------------------------
# D and the mechanism contrast D-G are SIGNIFICANTLY NEGATIVE for most of
# training on EVERY CIFAR-10 cell and turn positive only near the end.  Every
# number below was RE-DERIVED from the raw .out epoch series at write time --
# not quoted from prose -- with the SAME 5-epoch window plateau5 uses and the
# campaign's own WELCH-UNPAIRED convention:
#     g3m  (R34, n=9)  D    -0.301 (t -2.18, 1 of 9 seeds positive) @ep40
#                           -0.518 (t -4.06)                       @ep55
#                           +0.666 (t +7.08, 9 of 9 seeds)         @ep100
#                      D-G  -0.832 (t -4.14) @ep40 -> +0.495 (t +4.15) @ep100
#     cc1  (R18, n=3)  D    +0.020 @ep40, **-0.560 (t -5.20) @ep55**, +0.727 @ep100
#                      D-G  -0.945 @ep40 -> +0.715 @ep100
#     fa1  (R18, n=6)  D    -0.227 @ep40 -> +0.629 @ep100
#                      D-G  -0.426 @ep40 -> +0.630 @ep100
# (g3m's +0.666 / t 7.08 and D-G +0.495 / t 4.15 reproduce CORRECTIONS 116
# exactly, which is the check that this reader is the campaign's reader.)
# The guards are clean on all of them (g3m 36/36 box-free, rec_lo = rec_hi =
# 0.0000), so this is NOT clipping.  IT IS ALSO NOT beta-TRAVEL, and that is
# re-derived here rather than asserted.  With --weight-decay-meta 0 the Lion
# identity makes travel exactly ms*T, so a fixed number of nats is a fixed
# amount of meta-learning.  AT A MATCHED 5.0 NATS the three cells disagree by
# nearly a full point:
#     cc1  ms=1e-4, ep100 (5.00 nats)  D = +0.727
#     g3m  ms=1e-4, ep100 (5.00 nats)  D = +0.666
#     fa1  ms=3e-4, ep33  (4.95 nats)  D = -0.195   <-- opposite sign
# whereas at a matched FRACTION of the budget they agree (all three positive
# and large at t/T = 1).  D tracks t/T, the fraction of the budget elapsed --
# which is precisely why extending T is the experiment that decides the paper.
#
# **UNTIL THIS BATCH RUNS, EVERY HEADLINE IN THE PAPER IS A CLAIM ABOUT EPOCHS
# 95-100 OF 100.**  The campaign has already had exactly one headline invert
# this way (nodewise - layerwise: -3.946 @ep10, 0/7 seeds -> +1.258 @ep40, 7/7;
# analysis/c58_horizon_reversal.py was built for it) and that instrument was
# never pointed at the tail arms.
#
# -----------------------------------------------------------------------------
# WHY THIS CELL AND NOT A FLATTERING ONE
# -----------------------------------------------------------------------------
# This is cc1's config exactly -- ResNet18 / CIFAR-10 / ms=1e-4 / alpha0=1e-3 /
# batch 100 / AUGMENT=1 / SGDm+Lion -- for three reasons:
#   (i)   it is the cell where D spends the LONGEST negative.  Re-derived from
#         cc1's own .out series at write time (Welch, n=3v3): D = +0.625 @ep25,
#         +0.020 @ep40, **-0.560 @ep55**, +0.243 @ep70, +0.443 @ep85,
#         +0.727 @ep100 -- and the ep100 value reproduces the CSV's plateau5
#         reading EXACTLY, which is the second check on the reader.  The honest
#         worst case, not the flattering one.
#   (ii)  it is the cheapest per epoch of the four-arm cells (R18, not R34).
#   (iii) it is the ONLY cell that carries all four arms in one batch at n>=3
#         with a published D, G, D-G AND T, so every quantity this batch reads
#         has a 100-epoch comparator measured on the identical configuration.
#
# -----------------------------------------------------------------------------
# **THE READING IS WITHIN-RUN, AND THAT IS THE WHOLE DESIGN.**
# -----------------------------------------------------------------------------
# D(100), D(200) and D(300) are all read from THE SAME SIXTEEN RUNS, off the
# .out epoch series.  This is not a budget ladder and it is NOT three batches:
#   * the batch random effect (STANDING RULE 14, sd_batch ~ 0.21 pp,
#     F(62,85)=5.47, p=6.9e-13) is IDENTICAL across the three readings and
#     cancels EXACTLY in D(300) - D(100).  A budget ladder run as separate
#     submissions would have put 2*sd_batch^2 inside the very trend the batch
#     exists to measure -- the F1 defect that killed g3d/g34.
#   * the seed is identical across the three readings, so the trend is a
#     within-run, within-seed quantity even though the arm contrast is Welch.
# THIS IS ONLY LEGAL BECAUSE NOTHING IN THE RUN DEPENDS ON THE BUDGET.
# GUARD 1e PROVES IT rather than assuming it: `args.num_epochs` occurs in
# train.py exactly twice -- the argparse declaration and
# `for epoch in range(args.num_epochs)` -- and NOWHERE in HF.py.  There is no
# schedule, no T_max, no warmup, no total-steps term.  Epochs 0-99 of a
# 300-epoch run are therefore DISTRIBUTIONALLY IDENTICAL to a 100-epoch run at
# the same seed, which is what makes D(100) a legitimate INTERNAL CONTROL and
# not a new estimand.  GUARD 1b-7 independently pins SCHED=none and asserts
# that HF.py's PATCH_SCHED multiplier is 1.0 on BOTH of its two paths
# (SCHED_TOTAL absent -> T<=0 -> 1.0; and 'none' matches neither 'cosine' nor
# 'linear' -> 1.0).
#
# -----------------------------------------------------------------------------
# THE PRE-REGISTRATION.  FIXED HERE, BEFORE ANY hz3 RUN EXISTS.
# -----------------------------------------------------------------------------
# INTERNAL CONTROL, READ FIRST AND ABSOLUTELY GATING.
#   D(100) computed INSIDE this batch must land in [+0.20, +1.00].
#   (cc1 +0.727 se 0.200; the R18 ms=1e-4 IV pool +0.5805 se 0.0939, Q 0.88 on
#   2 df.)  The band is deliberately WIDE because it is a CROSS-BOX reading:
#   the floor moved from -15 to -30 (see THE BOX, below) and fa1 measured that
#   this box class is NOT inert.  Its job is to detect that the box move, the
#   300-epoch schedule-free run, or anything else has broken the cell.
#   **IF THE CONTROL FAILS THE BATCH IS VOID AND D(300) IS NOT READ.**
#
# PRIMARY.   D(300) > 0 at |t| >= 2.  At the re-derived planning sd (0.1743 on
#   33 df) and n=4, se(D) = 0.1233, so |t| >= 2 means D(300) >= +0.247.
#   PREDICTED: D(300) in [+0.4, +1.2], at or above D(100) -- D(t) is still
#   rising steeply at ep100 in all three cells (+0.03 -> +0.67 over ep70-100 on
#   g3m) and there is no schedule to end.
# SECONDARY. (D-G)(300) > 0 at |t| >= 2.  se(D-G) = 0.1743 within batch.
# SHAPE.     D(300) - D(100), banded GROWS / SATURATES / DECAYS at +-0.20.
# DESCRIPTIVE ONLY.  G(300); the in-batch count contrast U = chunk2325 -
#   chunk777; T = nodewise1d - nodewise, which is COUNT-CONFOUNDED by
#   construction (14,420 -> 4,851 = 0.4731 decades) and is NOT tail removal;
#   the D(t)/G(t)/(D-G)(t) trajectory at 100/200/300; the seed-blocked estimate;
#   the GPU-class contrast.
#
# REFUTATION, FIXED HERE.  D(300) <= +0.20, OR D(300) < 0.5 x D(100) WITH a
#   monotone decline across the three registered readings.  Either outcome
#   means the effect is a fixed-budget phenomenon: the headline must be
#   rewritten as "at a 100-epoch budget", the mechanism claim goes with it, and
#   the parent paper's own unexplained ImageNet null ("the blockwise versions
#   showed no improvement") becomes the correct long-budget reading rather than
#   an anomaly.
#
# **THIS BATCH CANNOT COME OUT UNINFORMATIVE.**  Grows, saturates and fades are
# all publishable and all three change what the abstract may say.
#
# -----------------------------------------------------------------------------
# THE BOX.  -30:-2.3026.  THE FLOOR MOVED AND THE CEILING DID NOT.
# -----------------------------------------------------------------------------
# HF.py's Lion meta update with --weight-decay-meta 0 gives |dbeta| = ms
# EXACTLY per step, so beta is confined to [beta_0 - ms*T, beta_0 + ms*T] for
# ANY velocity profile.  beta_0 = ln(1e-3) = -6.907755; T = 300 x 500 = 150,000;
# ms*T = 15.0000 nats.
#   FLOOR   -30      is 23.0922 nats away  -> UNREACHABLE, 8.0922 nats of slack.
#   FLOOR   -15      is  8.0922 nats away  -> REACHABLE from epoch 161.8.
#                    **THIS IS WHY THE FLOOR MOVED.**  cc1's own box would have
#                    clamped for the last 46% of this run.  GUARD 8 computes
#                    BOTH and refuses the reachable one (RULE 13).
#   CEILING -2.3026  is  4.6052 nats away  -> REACHABLE from epoch 92.1.
# The ceiling is held at -2.3026, UNCHANGED from every headline cell (RULE 10),
# because the measured beta in this box class has never exceeded -3.499.  But
# reachable-from-epoch-92.1 is 8% of a 100-epoch run and **69% of this one**,
# and that is a DISCLOSED, FIRST-CLASS RISK, not a footnote:
#   * the scorer reports rec_lo AND rec_hi PER SEED PER ARM, computed over the
#     SAME 5-epoch window as each accuracy reading, so occupancy is reported
#     beside D(100), D(200) and D(300) separately;
#   * an arm with more than 50% of its seeds bound at EITHER rail is VOID and
#     must be re-run (floor: at -40; ceiling: the ceiling cannot be released
#     without leaving the box class every published D was measured in, so a
#     ceiling bind is reported as a LIMIT ON THE READING, not patched away);
#   * a contrast whose two arms differ by more than 0.10 absolute in occupancy
#     at either rail is VOID -- the contrast would be confounded with the guard.
# -30:-2.3026 is NOT a novel box: it is wc5's, already run on ResNet18
# (bin/c50_wideclip_ladder.sh), and GUARD 2g counts its existing rows.
#
# -----------------------------------------------------------------------------
# HARDWARE IS ASSIGNED BY SEED.  CLOSEOUT 2.2(3).
# -----------------------------------------------------------------------------
# The audit found mm1 (chunk 1xL4 + 2xA100 vs node 3xA100) and ar1's D leg
# (chunk 1x2080Ti + 2xL4 vs node 2x2080Ti + 1xL4) ARM-IMBALANCED ON HARDWARE,
# and neither FINDINGS nor the audit reported it.  This batch removes the
# failure mode by construction: **the GPU class is a function of the SEED, so
# all four arms of a seed share it.**
#     seeds 0,1 -> gpu-l4-24g       (8 jobs, cluster_a's dedicated L4 cap is 8)
#     seeds 2,3 -> gpu-2080ti-11g   (8 jobs, dedicated 2080ti cap is 12)
# Every arm is then 2 L4 + 2 2080ti, every within-seed difference is
# hardware-free, and the class becomes a SEED-LEVEL BLOCK.  That is also why
# the scorer reports a seed-blocked estimate as a registered SECONDARY: here,
# and only here, blocking on seed removes a real nuisance rather than the
# statistically null seed label (SEED F=1.21, p=0.213).  The Welch-unpaired
# figure remains PRIMARY so that D(300) is comparable to every published D.
# GUARD 1b-6 asserts the map is a bijection on the seeds and GUARD 6d asserts
# each class stays inside its cap.
#
# -----------------------------------------------------------------------------
# THE WALL.  **10:00:00, AND THIS IS A DELIBERATE DEVIATION FROM 08:30:00.**
# -----------------------------------------------------------------------------
# gpu-short (4:00:00 cap) is EXCLUDED and cannot be used by this batch at all.
# GUARD 7 projects the worst case with TWO instruments and takes the WORSE:
#   (A) DIRECT.  The worst measured per-epoch rate over the FOUR SUBMITTED ARMS
#       on nodes REACHABLE in PARTS -- 1.140 min/ep (ar1-c23-s0, [HOST_8132501753],
#       chunk2325, 114 min / 100 ep) -> 342 min at 300 ep.  08:30 = 1.49x.
#   (B) CONSERVATIVE.  The worst measured layerwise rate on a reachable node
#       (0.768 min/ep) x the worst measured arm/layerwise ratio (chunk2325 at
#       1.806) -> 1.387 min/ep -> 416 min at 300 ep.  08:30 = **1.22x**, BELOW
#       the 1.40x registered floor.
# Instrument (B) exists because the slowest reachable 2080ti nodes have no
# chunk-arm run on them at all, so (A) is measured where the hardware happens
# to be fast.  At 10:00:00 = 600 min the conservative headroom is 1.44x and the
# direct is 1.75x.  Truncation is not cosmetic in this corpus -- rs-node runs
# killed at epochs 24-59 FLIPPED a rung's argmax -- and at 300 epochs a
# truncated run destroys the ONLY thing the batch is for.  Both partitions cap
# at 7-00:00:00, so the longer wall costs nothing but backfill priority against
# an EMPTY queue.
#
# -----------------------------------------------------------------------------
# WHAT THIS BATCH MAY **NOT** CLAIM.  Registered before any data exists.
# -----------------------------------------------------------------------------
#   * NOT a RULE-11 result.  No arm's own ms argmax is measured at 300 epochs,
#     and the scorer prints that in its own output.
#   * NOT a fifth replication of the R18 D series.  It is a HORIZON control on

#   * NO FIELD STATISTIC OF ANY KIND.  PROBE=5 is exported for BOX OCCUPANCY

#   * NO cross-box amendment to cc1's, mm1's, pp1's, ar1's, fa1's or g3m's own
#     readings, and no claim that D(100) here supersedes cc1's D.
#   * T = nodewise1d - nodewise is COUNT-CONFOUNDED (0.4731 decades) and is
#     DESCRIPTIVE ONLY.  It is NOT tail removal and the scorer refuses the label.
#   * NOTHING about ResNet34, ResNet50 or CIFAR-100.
#
# STANDING RULES HONOURED: 10 (the arm set and the ceiling are cc1's,
