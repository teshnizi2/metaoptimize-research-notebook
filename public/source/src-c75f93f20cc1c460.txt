#!/bin/bash
# =============================================================================
# Cycle 52 -- WHERE DOES THE NODEWISE MINIMUM TURN ON?  cluster_a.  12 jobs.  `ns5-*`.
#
# OPEN QUESTION IT ANSWERS, and it is the stated weakness of this tick's own new
# result rather than a new direction.
#
#   CORRECTIONS 70 records: N_eff/m is non-monotone in the group count with its
#   MINIMUM AT NODEWISE, in 9 of 9 (family x box) cells -- but **only at
#   ms=1e-3**.  At ms=1e-4 the argmin is WEIGHTWISE (ml5 m4: lay 0.700 / node
#   0.170 / w 0.129).  70 reports that as "a genuine counterexample [that] is
#   NOT swept under the rug" and scopes the claim to the ms=1e-3 operating point.
#
#   A SCOPING ADMISSION IS NOT A CHARACTERISATION.  As written, 70 says "true at
#   one meta-stepsize, false at another, and we do not know where the boundary
#   is."  That is the version a referee attacks.  This batch locates the
#   boundary, at which point the same fact becomes a statement about WHEN the
#   shape holds -- which is publishable and defensible.
#
# WHAT WAS CHECKED FIRST, and it changes the design.
#   The ms=1e-4 counterexample could have been a box artefact like everything
#   else this tick.  It is NOT.  Measured on `../probes_ml5` at coordinate
#   resolution, ml5's m4 arms never touch either guard even in the NARROW box:
#       arm            %rec LO  %rec HI  %Q4 LO  %Q4 HI   final min  final max
#       ml5 w    m4      0.0      0.0      0.0     0.0      -7.891     -5.931
#       ml5 node m4      0.0      0.0      0.0     0.0      -7.899     -5.912
#       ml5 lay  m4      0.0      0.0      0.0     0.0      -7.888     -5.907
#   (contrast ml5 w m3, the SAME box: 8.2% / 7.4%, final min pinned at -15.000.)
#   **So the counterexample is clean and must be taken at face value.**  It also
#   means the ms=1e-4 rung is a valid BOX-FREE control despite its nominal box,
#   and this batch does not need to re-run it.
#
# WHY THE LADDER GOES DOWN FROM 1e-3 AND NOT UP.  Travel of the top coordinate
# in 20 epochs from beta0 = -6.909, measured:
#       ms=1e-4   final max -5.931   travelled 0.978 log units
#       ms=1e-3   final max -2.158   travelled 4.751 log units
#   Travel grows sublinearly in ms (~4.9x for 10x), so ms=3e-3 projects to
#   ~10 log units of travel, i.e. final max ~ +3.4 -- past ANY usable ceiling.
#   **There is no box-free configuration above ms=1e-3 at this budget**, which is
#   the same sentence FINDINGS 51.7 got wrong at ms=1e-3 and which is stated here
#   only because the travel is now MEASURED at two stepsizes rather than
#   extrapolated from a startup velocity (STANDING RULE 7, CORRECTIONS 67).
#   It is also why ms=1e-2 has been boundary-dominated all along (CORRECTIONS 62).
#   Going DOWN is therefore both the only fundable direction and the direction
#   the counterexample lives in.
#
# THE DESIGN.  One variable: the meta-stepsize.  Byte-identical to `cl5-*-cU-*`
# (R18/CIFAR-10, SGDm/Lion, alpha0=1e-3, AUGMENT=1, BETA_CLIP=-30:0.0, 20 epochs,
# rungs w/node/lay) except --meta-stepsize.  ms in {2e-4, 5e-4}, seeds 0-1.
# With the two controls already on disk this is a FOUR-POINT box-free ladder:
#       ms=1e-4   ml5 m4      argmin **w**     (0.700 / 0.170 / 0.129)   n=3
#       ms=2e-4   NEW, 6 jobs
#       ms=5e-4   NEW, 6 jobs
#       ms=1e-3   cl5 cU      argmin **node**  (0.726 / 0.402 / 0.504)   n=3
#
# PRE-REGISTERED PREDICTIONS -- score against these, not against what lands.
#
#   (N0) VALIDITY GATE.
#        1. beta must MOVE: beta_true_max != beta_true_min on the last record, 12/12.
#        2. n_records == 2000; n_beta byte-matches cl5: w 11,173,962 / node 14,420
#           / lay 62.  A mismatch voids the ladder.
#
#   (N0.3) **THE BOX-FREE GATE, SCORED FIRST**, for the fourth time this tick.
#        < 5% of records at either guard, per rung, at BOTH new stepsizes, using
#        `beta_true_min`/`beta_true_max` AND PATCH_CLIPCOUNT's per-coordinate
#        counts (STANDING RULES 5, 6).  This one is expected to pass trivially --
#        ms=1e-3 already passed at 0.0% and a SMALLER stepsize travels LESS -- so
#        a FAILURE here would mean something other than the meta-stepsize changed,
#        and the batch would be void rather than interesting.  It is scored anyway
#        because "expected to pass trivially" is the exact reasoning that made
#        cycle 50 move the wrong wall.
#
#   (N1) THE PRIMARY TEST -- WHERE DOES argmin FLIP?
#        argmin of N_eff/m over {lay, node, w}; VARIANCE instrument, STEADY half.
#        Controls: ms=1e-4 -> **w**;  ms=1e-3 -> **node**.
#        PREDICTION: the flip is MONOTONE in ms -- exactly one crossing in
#        [1e-4, 1e-3].  So the admissible outcomes are (w, w), (w, node) or
#        (node, node) at (2e-4, 5e-4).
#        REFUTATION: **(node, w)** -- argmin node at 2e-4 and back to w at 5e-4.
#          --> the shape is not a monotone function of the meta-stepsize, 70's
#              one-line scoping is inadequate, and the result must be reported as
#              holding at a POINT rather than on an interval.
#        Report the full three-number profile at every rung, never just the argmin:
#        an argmin is a summary of a curve, and CORRECTIONS' standing rule about
#        `s` (§51-replacement) applies to this summary for the same reason.
#
#   (N2) THE MECHANISM CANDIDATE, REGISTERED NOW SO IT CANNOT BE FITTED AFTER.
#        At ms=1e-4 beta travels 0.978 log units in 20 epochs; at ms=1e-3 it
#        travels 4.751.  The m4 arm may simply be too close to the FROZEN limit
#        for adaptation to have produced the shape at all -- in which case the
#        governing variable is not the meta-stepsize but the ADAPTATION EXTENT.
#        PREDICTION: the argmin flips to `node` at the stepsize whose weightwise
#        beta SPAN first exceeds ~5 log units, and the flip tracks span better
#        than it tracks ms.  Report `beta span` (max - min on the last record)
#        for every arm alongside the argmin; the four-point ladder is enough to
#        tell a span threshold from a stepsize threshold because span grows
#        SUBLINEARLY in ms (measured 4.9x for 10x), so the two orderings are not
#        the same ordering.
#        --> If confirmed, CORRECTIONS 70 gets rewritten in terms of adaptation
#            extent instead of meta-stepsize, which is a better statement: it
#            transfers across optimizers and budgets, and it predicts that the
#            nodewise minimum should also appear at ms=1e-4 given a LONGER run.
#            That prediction would then be directly testable against `bl5-*`.
#        --> If refuted (the flip tracks ms and not span), say so; 70 stays
#            scoped to the meta-stepsize and the mechanism stays open.
#
#   (N3) ACCURACY, reported regardless and not a test.  Plateau per arm against
#        cl5-cU (w 68.578 / node 72.787 / lay 74.426) and ml5-m4.  A smaller
#        meta-stepsize should train more slowly; this is recorded, not scored.
#
#   RESOLUTION, per CORRECTIONS 33, computed BEFORE submission.  rho_min is set by
#   T and m and does not depend on the meta-stepsize, so the cl5 floors carry over:
#       weightwise  ~8.5e-09   RESOLVES
#       nodewise    ~7.0e-06   RESOLVES
#       layerwise   ~1.5e-03   MARGINAL at m=62, as always.  A layerwise null is a
#                              BOUND, never an absence -- and N1 is an argmin over
#                              three rungs, so an unresolved layerwise rung makes
#                              the argmin UNDECIDABLE for that arm rather than
#                              defaulting it to one of the other two.  Say which.
#
# NOT INCLUDED, deliberately:
#   * ms >= 3e-3.  Measured travel says it cannot be run box-free at this budget.
#     Running it and reporting the argmin would be quoting a boundary-dominated
#     arm, which is what CORRECTIONS 62 forbids.
#   * Other families.  The counterexample is at R18 and so is the ms axis that
#     produced it.  Adding R10/R34 before the R18 boundary is located would be
#     spending on breadth before the thing being characterised is characterised.
#   * A third seed.  n=2 at the new rungs against n=3 at both controls; the
#     statistic is an ARGMIN over gaps of 0.1-0.3, not a mean difference of 0.006,
#     so n=2 resolves it.  If two rungs come back within 0.02 of each other, say
#     UNDECIDED and buy the third seed then.
#
# WHY cluster_a.  cluster_a is idle (uc6 complete) and cluster_b is running `bl5-*`.  The
# controls are split -- ml5/cl5 are on cluster_b -- so this batch breaks the
# by-comparator rule of CORRECTIONS 46(6) deliberately and says so.  The
# comparison is via N_eff/m computed by a shared, selftested instrument on probe
# files, not via raw accuracy, and the two accounts have byte-identical HF.py
# after PATCH_CLIPCOUNT was applied to both (CORRECTIONS 63).  **If N0's n_beta
# byte-match fails, that assumption is wrong and the batch is void.**
#
# STRUCTURAL CHECKS BEFORE USING ANY NUMBER (Rule 4)
#   1. N0.1, N0.2, N0.3 above, run not assumed, N0.3 FIRST
#   2. python3 analysis/c52_boxfree.py --selftest      (27/27)
#   3. python3 analysis/neff_instrument.py --selftest  (19/19)
#   4. python3 analysis/probe5_window.py --selftest    (41/41)
#   5. Window scan on every arm.  Never quote a profile number without its window.
#
# USAGE
#   bash c52_nodemin_onset.sh            # dry run
#   bash c52_nodemin_onset.sh --submit   # submits, ONLY if the guards below pass
# =============================================================================
set -u

WS=/cluster/account_a/metaopt                   # cluster_a
RUNNER=$WS/jobs/run_cifar.sh
HF=$WS/MetaOptimize/codes/Supervised_tasks/MetaOptimize/cifar10/Optimizers/HF.py
SAVE=$WS/runs/ns5
PARTS=gpu-short,gpu-l4-24g,gpu-2080ti-11g,gpu-mig-40g,gpu-a100-80g
USER_NAME=account_a
PEND_CAP=40
NJOBS=12
BOX=-30:0.0
SUBMIT=0
[ "${1:-}" = "--submit" ] && SUBMIT=1

echo "=== c52 NODEWISE-MINIMUM ONSET LADDER + PROBE5 (cluster_a) ==="
echo "    BETA_CLIP=$BOX  ms in {2e-4, 5e-4};  controls ml5-m4 (1e-4) and cl5-cU (1e-3)"

for P in PATCH_PROBE5 PATCH_PROBE5_FIX PATCH_CLIPCOUNT; do
  grep -q "$P" "$HF" 2>/dev/null || { echo "GUARD FAIL: $P not present in $HF"; exit 1; }
done
echo "guard 1: PATCH_PROBE5 + PATCH_PROBE5_FIX + PATCH_CLIPCOUNT present  OK"

python3 -c "import py_compile; py_compile.compile('$HF', doraise=True)" 2>/dev/null || {
  echo "GUARD FAIL: $HF does not compile"; exit 1; }
echo "guard 2: HF.py compiles  OK"

# GUARD 3 -- "byte-matched except one field" is a CLAIM (the uc5 lesson).  The
# control is cl5-cU and the ONLY field that may differ is --meta-stepsize.
CL5=$(dirname "$0")/c51_ceiling_ladder.sh
if [ -r "$CL5" ]; then
  for f in "ResNet18" "CIFAR10" "SGDm" "Lion" "alpha0 1e-3" "num-epochs 20"; do
    grep -q -- "$f" "$CL5" || { echo "GUARD FAIL: '$f' absent from the cl5 control"; exit 1; }
  done
  echo "guard 3: cl5 control is R18/CIFAR10/SGDm/Lion/alpha0=1e-3 at 20 epochs  OK"
else
  echo "guard 3: c51_ceiling_ladder.sh not readable here -- SKIPPED (say so in FINDINGS)"
fi

FS=$(sshare -U -u "$USER_NAME" -n -o FairShare 2>/dev/null | tr -d ' ' | head -1)
PEND=$(squeue -h -u "$USER_NAME" -t PENDING 2>/dev/null | wc -l | tr -d ' ')
echo "guard 4: FairShare=${FS:-unknown} (informational), pending=$PEND, adding $NJOBS"
if [ "$SUBMIT" = "1" ]; then
  [ "$((PEND + NJOBS))" -le "$PEND_CAP" ] || {
    echo "ABORT: $PEND pending + $NJOBS would exceed the $PEND_CAP cap"; exit 1; }
fi

mkdir -p "$SAVE"
N=0
FAIL=0
for MS in 2e-4:m2p4 5e-4:m5p4; do
  MSV=${MS%:*}; MST=${MS#*:}
  for G in layerwise nodewise weightwise; do
    case $G in
      layerwise)  TAG=lay  ;;
      nodewise)   TAG=node ;;
      weightwise) TAG=w    ;;
    esac
    for S in 0 1; do
      RN="ns5-${TAG}-${MST}-s${S}"
      PD="$SAVE/probe_${TAG}_${MST}_s${S}"
      CMD=(sbatch --job-name="$RN" --partition="$PARTS" --time=03:50:00
        --export="ALL,AUGMENT=1,BETA_CLIP=$BOX,PROBE=5,PROBE5=1,PROBE5_WRITE_EVERY=500,PROBE_DIR=$PD"
        "$RUNNER"
        --optimizer HF --alg-base SGDm --momentum-param-base 0.99 --weight-decay-base 0.1
        --alg-meta Lion --momentum-param-meta 0.99 --Lion-beta2-meta 0.9 --weight-decay-meta 0
        --dataset CIFAR10 --NN-name ResNet18 --batch-size 100
        --max-time 999:00:00 --gamma 1 --meta-stepsize "$MSV" --alpha0 1e-3
        --num-epochs 20 --stepsize-groups "$G" --seed "$S"
        --save-directory "$SAVE" --run-name "$RN")
      # Count what Slurm ACCEPTED, not what we tried (the c52_budget_ladder lesson:
      # it printed "9 SUBMITTED" while sbatch had rejected all 9 on --time).
      if [ "$SUBMIT" = "1" ]; then
        if "${CMD[@]}" >/dev/null; then N=$((N+1)); else FAIL=$((FAIL+1)); fi
      else
        N=$((N+1)); printf '%s\n' "${CMD[*]}"
      fi
    done
  done
done
echo "---- $N jobs ($( [ "$SUBMIT" = 1 ] && echo ACCEPTED BY SLURM || echo 'dry run, nothing submitted' )); $FAIL rejected ----"
[ "$FAIL" -gt 0 ] && echo "!!! $FAIL sbatch calls FAILED -- do not treat this batch as submitted"
echo "reduce with, IN THIS ORDER:"
echo "  1. python3 analysis/c52_boxfree.py                    # N0.3 BOX-FREE GATE -- FIRST"
echo "  2. python3 analysis/neff_instrument.py ../probes_ns5  # N1 -- the argmin, all 3 rungs"
echo "  3. python3 analysis/probe5_window.py ../probes_ns5    # window scan, always"
echo "  4. beta span per arm (last record, max-min) for N2 -- the adaptation-extent test"
