# -----------------------------------------------------------------------------
# WHAT IS BEING INTERVENED ON, AND WHY THE OBVIOUS INTERVENTION IS A NULL
# -----------------------------------------------------------------------------
# On the LIVE source (`Optimizers/HF.py`), a group's whole meta-signal is an
# UNNORMALISED SUM,
#     block_product():259  scalar    [sum([(u_*v_).sum() for u_,v_ in zip(u,v)])]
#                    :262  blockwise [torch.tensor([sum([(u[i]*v[i]).sum()
#                                      for i in group_indices]) for ...])]
# and `Lion_meta_update():957` consumes ONLY its sign:
#     beta = (1-ms*wd)*beta - ms*torch.sign(b2*momentum_meta + (1-b2)*z)
#     momentum_meta = mom*momentum_meta + (1-mom)*z        # zero-initialised
#
# CONSEQUENCE, PROVED NOT ARGUED (analysis/cX1_reduction_noop_proof.py, which
# drives the LIVE meta_update methods): `momentum_meta` is a zero-initialised
# LINEAR recursion in z, so dividing a GROUP's reduction by ANY positive
# per-group constant -- its tensor count, its parameter count -- divides the
# sign() argument by that constant and leaves the beta trajectory BITWISE
# IDENTICAL, at c up to 6.3e6.  "NORMALISE THE GROUP REDUCTION" IS A NULL BY
# CONSTRUCTION ON THIS OPTIMIZER AND IS NOT RUN HERE.
#
# The only reduction intervention with power is one that changes the RELATIVE
# WEIGHT OF TENSORS WITHIN a group.  PATCH_REDNORM adds exactly that, opt-in:
#     --stepsize-groups tn:<spec>   ->   z_G = sum_{i in G} <h_i,g_i> / numel_i
# It is INERT at every granularity whose groups hold one tensor (layerwise,
# nodewise, weightwise, nodewise1d, chunk*, permnode*) -- tests/test_rednorm.py
# R5 asserts that BITWISE -- so a {scalar, layerwise} x {standard, normalised}
# design would have THREE distinct cells, not four.  This batch therefore spends
# its arms where the intervention can bite.
#
# THREE THINGS WERE MEASURED ON THE LIVE OPTIMIZER BEFORE ANY ARM RAN, AND
# THEY CHANGED THE DESIGN.  analysis/cX1_reduction_probe.py wrapped the REAL
# optimizer at this EXACT cell and recorded all 62 per-tensor terms at every one
# of 6,000 meta-steps at `scalar`, `[49,13]` and `[50,12]`;
# analysis/cX1_reduction_report.py reads them; the full output is committed at
# results/crn1_reduction_probe/REPORT.txt.
#  (a) AN EQUAL VOTE PER TENSOR -- all size information discarded -- gives the
#      SAME sign as the unnormalised sum in 99.2% to 99.9% of steps at every
#      group of every configuration.  The sum's sign is NOT hijacked by the
#      large tensors.
#  (b) In the `[50,12]` COARSE group, REMOVING `layer4.0.bn2.weight` (tensor 50,
#      512 params) flips that group's sign in 0.0003 of steps -- three in ten
#      thousand -- yet moving that tensor across the cut costs 25.068667 pp.
#      THE CUT-POSITION CLIFF IS NOT A REDUCTION EFFECT.  The briefing's
#      sharpest prediction, that normalising should collapse the cliff, is
#      REFUTED AT THE MECHANISM LEVEL FOR ZERO GPU-HOURS.
#  (c) `tn:` does not neutralise size, it INVERTS it: the 1-D BatchNorm scales
#      and shifts are 65% of the tensors and 0.087% of the parameters, and
#      they hold 2.6-4.6% of a group's sum|t| under the standard reduction and
#      84-93% of it under 1/numel.  The same inversion raises tensor 50's
#      steering power from 0.0003 to 0.1470, a 490x increase, in the OPPOSITE
#      direction to the briefing's prediction.
#
# -----------------------------------------------------------------------------
# THE DESIGN.  6 arms x 3 seeds = 18 jobs, ONE submission.  100 epochs.
#   k01   scalar                    m = 1 FLOOR ANCHOR, in batch, MANDATORY
#   k01n  tn:scalar                 the same m = 1, vote handed to the BN params
#   k49   sets:1-49/50-62           == [49,13] EXACTLY (test_namesets N2)
#   k49n  tn:sets:1-49/50-62        the same partition, vote handed over
#   k50   sets:1-50/51-62           == [50,12] EXACTLY
#   k50n  tn:sets:1-50/51-62        the same partition, vote handed over
#   SEEDS {15,16,17} -- ZERO rows ANYWHERE in the corpus carry them.
#
# PRIMARY -- COMPOSITION.  Three SAME-PARTITION pairs.  Each pair is two
# OPPOSITE extreme weightings of one partition, disagreeing in sign on a
# MEASURED 7.62% to 19.10% of meta-steps.
#     P01 = k01n - k01,  P49 = k49n - k49,  P50 = k50n - k50
#   H-COMP-INERT  the composition of a group's meta-signal does not affect
#                 outcome.  POINT PREDICTIONS P01 = P49 = P50 = 0.
#   H-COMP-LIVE   it does.  The COMPLEMENT; it makes no point prediction, which

    za = [x.detach().double().reshape(-1) for x in built[a].block_product(U, V)]
    zb = [x.detach().double().reshape(-1) for x in built[b].block_product(U, V)]
    ratio = [float(y / x) if float(x) != 0 else float("inf")
             for x, y in zip(za[0], zb[0])]
    same = all(bool(torch.equal(x, y)) for x, y in zip(za, zb))
    print("         %-4s -> %-5s  z_std=%s  z_tn=%s  differ=%s"
          % (a, b, [float(x) for x in za[0]], [float(x) for x in zb[0]], not same))
    if same:
        print("!!! guard 4e: %s and %s give the SAME reduction" % (a, b)); bad += 1
    lines.append("REDUCTION_DIFFERS %s %s %d" % (a, b, 0 if same else 1))
    # and the per-group ratios must NOT be a single common constant, or the
    # intervention would be the per-group rescaling the no-op proof kills.
    if len(ratio) > 1:
        spread = max(ratio) / min(ratio) if min(ratio) > 0 else float("inf")
        print("         per-group z_tn/z_std ratios %s (spread %.4g)"
              % (["%.6g" % r for r in ratio], spread))
        lines.append("RATIO_SPREAD %s %.6g" % (b, spread))

    print("         %-10s tn: reduction BITWISE identical: %s" % (s, ident))
    if not ident:
        print("!!! guard 4f: tn: changed %s" % s); bad += 1
    lines.append("SINGLE_TENSOR_INERT %s %d" % (s, 1 if ident else 0))
