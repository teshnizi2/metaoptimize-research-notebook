#!/bin/bash
# =============================================================================
# Cycle 52 -- THE BOX-FREE BUDGET LADDER.  Runs on cluster_b.  9 jobs.  Tag `bl5-*`.
#
# OPEN QUESTION IT ANSWERS, and after this tick it is the LAST untested threat
# to the campaign's headline.
#
#   CORRECTIONS 59: "at the adapted operating point per-weight meta-gradients
#   carry 16%-55% of the independent information their count implies."
#   Cycle 52 closed the BOX threat: the number is unchanged when the entire
#   BETA_CLIP box is removed (R18 0.4808 -> 0.5045, R10 0.1632 -> 0.1571 against
#   a null moving -0.004; FINDINGS 52.2/52.3).  What is left is the BUDGET:
#
#     EVERY N_eff/m THIS CAMPAIGN HAS EVER QUOTED IS FROM A 20-EPOCH RUN,
#     AND CORRECTIONS 65 ESTABLISHED THAT THE SYSTEM IS NOT CONVERGED AT 20.
#
#   65's own words: with the floor moved out of the way "the minimum log-stepsize
#   is still descending at 89-100% of max Lion speed in the last quarter, 9 of 9
#   arms", which is why the phrase "at the adapted equilibrium" was narrowed to
#   "at the adapted operating point".  A referee reads that sentence and asks the
#   obvious question: is 0.50 an operating point, or the value N_eff/m happens to
#   have while still moving?  Nobody has run the ladder.
#
# WHY THIS BATCH IS FUNDABLE ONLY NOW, and it overturns this campaign's own
# written projection.
#   The cycle-51 PRE-REGISTERED ADDENDUM (commit 13b22ed) says:
#     "the ceiling is projected to bind anyway in r10/c100, because the top
#      coordinate climbs at 92-100pct of max Lion speed; there is no box-free
#      configuration at this budget."
#   That is refuted by measurement (FINDINGS 52.1).  92-100% is the STARTUP
#   velocity.  The top coordinate DECELERATES ~12x.  Measured on the last
#   quarter of the box-free R18 arms, with 100 records = 1 epoch:
#       arm                 v_Q4/vmax   final max   headroom   extra epochs
#       cl5 w    cU (R18)      0.076      -2.158      2.158        56.6
#       cl5 node cU (R18)      0.053      -3.339      3.339       125.9
#       cl5 lay  cU (R18)     -0.180      -5.644      5.644         inf  (descending)
#       uc5 r10 w   (R10)      0.289      -0.975      0.975         6.7
#       uc5 r34 w   (R34)      0.032      -2.566      2.566       158.1
#   R18 has ~57 epochs of ceiling headroom at ms=1e-3.  **A 40-epoch box-free run
#   at R18 is affordable with a 17-epoch margin.  R10 has ~7 and is NOT fundable
#   -- that is why this ladder is R18-only and says so.**
#
# >>> AMENDMENT, WRITTEN AFTER SUBMISSION AND LABELLED AS SUCH (cycle 52). <<<
#   The table above is the MEAN TRAJECTORY across seeds.  The right statistic for
#   "can I afford 40 epochs" is the WORST SEED, and it is 2.5x smaller:
#       cl5 w    cU (R18)   v_Q4/vmax 0.174   final max -1.984   **22.8 epochs**
#       cl5 node cU (R18)   0.065             -3.313             102.7
#       cl5 lay  cU (R18)  -0.130 (down)      -5.527             inf
#       uc5 r10 w   (R10)   0.345             -0.964             **5.6 epochs**
#       uc5 r34 w   (R34)   0.074             -2.524             68.1
#   So this batch spends 20 extra epochs against 22.8 of worst-seed headroom.
#   **THAT IS MARGINAL, NOT A 17-EPOCH MARGIN.  The sentence above is wrong and
#   is left in place, struck, rather than quietly edited.**
#   It remains fundable because the projection is an UPPER BOUND on the climb --
#   velocity has fallen 0.95 vmax (startup) -> 0.17 (Q4) and is still falling --
#   so true headroom exceeds the linear extrapolation.  But "upper bound" is the
#   reasoning FINDINGS 51.7 got wrong in the other direction, so it earns a GATE
#   and not a presumption.  **B0.3 is scored first for exactly this reason, and
#   if the weightwise arm binds, its first_hi record IS the result** -- the first
#   direct measurement of the budget at which a box becomes unavoidable.
#   NOTHING IN THE B0-B4 PREDICTIONS CHANGES.  Only this justification does.
#
# THE DESIGN.  One variable: the budget.  Byte-identical to `cl5-*-cU-*`
# (R18/CIFAR-10, SGDm/Lion, ms=1e-3, alpha0=1e-3, AUGMENT=1, BETA_CLIP=-30:0.0,
# rungs w/node/lay, seeds 0-2) except **--num-epochs 20 -> 40**.
# The 20-epoch rung is ALREADY ON DISK at n=3, so 9 jobs buy a 2-point ladder.
# The probe samples every 5 steps, so 40 epochs writes 4000 records, and
# probe5_window's slices are FRACTIONAL -- "steady .5-1" is records 2000-4000.
#
# PRE-REGISTERED PREDICTIONS -- score against these, not against what lands.
#
#   (B0) VALIDITY GATE.
#        1. beta must MOVE: beta_true_max != beta_true_min on the last record, 9/9.
#        2. n_records == 4000 (NOT 2000 -- a 2000 here means the probe stride
#           changed and the window slices no longer mean what they mean in cl5).
#        3. n_beta byte-matches cl5: w 11,173,962 / node 14,420 / lay 62.
#
#   (B0.3) **THE BOX-FREE GATE, SCORED FIRST.**  The whole batch rests on the
#        headroom extrapolation above, and an extrapolation is not a measurement.
#        Per-coordinate occupancy at BOTH guards, over all 4000 records, from
#        `beta_true_min`/`beta_true_max` AND from PATCH_CLIPCOUNT's
#        n_at_lo/n_at_hi/n_beta (STANDING RULES 5 and 6).
#        BAR: < 5% of records at either guard, per rung.
#        IF AN ARM EXCEEDS IT, that arm's B1 is **UNINTERPRETABLE, NOT REFUTED**,
#        and the record index at which it first bound is itself the result --
#        it is the first direct measurement of the budget at which a box becomes
#        unavoidable, which is exactly what the addendum guessed at and got wrong.
#        Report `first_hi` and the epoch it corresponds to, per rung.
#
#   (B1) THE PRIMARY TEST.  N_eff/m, weightwise, VARIANCE instrument, STEADY
#        half (records 2000-4000) -- the only quotable combination.
#        Control: **0.5045** (cl5-w-cU, 20 epochs, steady half = records 1000-2000).
#        PASS (STATIONARY): within +-0.10, i.e. [0.40, 0.60].
#          --> N_eff/m is an operating point, not a transient.  The headline is
#              budget-robust as well as box-free, and "at the adapted operating
#              point" can be written without a budget caveat.
#        REFUTATION (DRIFTING): outside that band.
#          --> Every N_eff/m must be quoted WITH ITS BUDGET, and the 4-family
#              range needs a budget column exactly as it nearly needed a box one.
#        DIRECTION, stated now so a confirmation cannot be fitted afterwards:
#          I predict it moves **DOWN** (more agreement, less effective
#          information), because beta keeps spreading -- span 13.1 log units at
#          record 2000 and still widening -- and a wider spread concentrates the
#          meta-gradient onto the few fastest coordinates.  If it moves UP, the
#          prediction is wrong and that gets written down as such.
#        WHY +-0.10: the same bar X1, U1 and V1 used.  Using a different bar for
#        the test you care more about is how a moving target gets built.
#
#   (B1.5) **THE INTERNAL REPLICATION, AND IT IS WHAT MAKES B1 INTERPRETABLE.**
#        Compute N_eff/m on the 40-epoch runs restricted to records 1000-2000 --
#        the SAME ABSOLUTE WINDOW as the 20-epoch control, i.e. the same wall
#        clock of training.  It must land within +-0.10 of 0.5045.
#        IF IT DOES NOT, the two budgets differ for some reason OTHER than budget
#        (seed draw, node, dataloader order) and B1 is uninterpretable -- the
#        dose-check lesson, applied to a budget contrast instead of a box one.
#        This needs one line of analysis that does not exist yet:
#        `probe5_window.reduce_dir(d, windows=(("mid .25-.5", (0.25, 0.5)),))`
#        -- the windows argument is already there and the slices are fractional,
#        so 0.25-0.5 of a 4000-record run IS records 1000-2000.  Add it to
#        `neff_instrument.py` as an OPTION; do not change its default.
#
#   (B2) THE PROFILE.  b(steady, k^-b across w/node/lay).  Control 0.071
#        (cl5 cU).  PASS if within 0.05 -- the bar R18 met across four boxes
#        (span 0.029) and R10 met across two (0.003).
#        SECONDARY to B1: b is a 3-point fit and N_eff/m is not a fit at all.
#        If they disagree, report both and claim neither (cycle 50's C2 lesson).
#
#   (B2.5) THE SHAPE, tested for the first time as a PREDICTION rather than
#        observed.  FINDINGS 52.5: N_eff/m is non-monotone in the group count
#        with its MINIMUM AT NODEWISE, in 4 of 4 families and under all 4 boxes
#        (R18 cU: lay 0.726 / node 0.402 / w 0.504).
#        PREDICTION: the ordering node < w < lay survives to 40 epochs.
#        REFUTATION: any other ordering.  --> the shape is budget-specific and
#        must not be written as a property of the partition.
#        This is free -- the same three rungs are already being run for B2.
#
#   (B3) ACCURACY, reported regardless and NOT a test.  40 epochs should simply
#        beat 20 (control plateaus: w 68.578 / node 72.787 / lay 74.426).  It is
#        recorded because a plateau that does NOT improve would mean the run is
#        not actually training longer, which would void B1 by a different route.
#
#   (B4) THE VELOCITY, recorded because it is the addendum's own quantity and
#        this is the only batch that can measure it past 20 epochs.  Report
#        v_Q4/vmax of the top coordinate at 40 epochs against 0.076 at 20.
#        If it keeps decelerating, the "no box-free configuration" claim is not
#        merely wrong at this budget but wrong in the limit, and the campaign can
#        stop treating the box as a live threat at R18 entirely.
#
#   RESOLUTION, per CORRECTIONS 33, computed BEFORE submission.  rho_min falls
#   as 1/sqrt(T), and T doubles from 1000 to 2000 steady records, so every floor
#   IMPROVES by ~1.41x relative to the cl5 values:
#       rung        rho_min (T=2000 steady, 3 seeds)   verdict at ms=1e-3
#       weightwise  ~6.0e-09                           RESOLVES comfortably
#       nodewise    ~5.0e-06                           RESOLVES
#       layerwise   ~1.1e-03                           MARGINAL, as always at
#                                                      m=62.  A layerwise null is
#                                                      a BOUND, never an absence.
#   This is the FIRST batch of the campaign whose resolution improves rather
#   than merely holds, and it improves on the rung the headline is quoted at.
#
# NOT INCLUDED, deliberately:
#   * R10 and CIFAR-100.  R10 has 6.7 epochs of box-free headroom (measured); a
#     40-epoch R10 run would bind the ceiling around epoch 27 and would be
#     measuring the box again.  Running it anyway and reporting it as a budget
#     result is precisely the error cycle 50 made.
#   * ms=1e-2.  Boundary-dominated at both walls (CORRECTIONS 62); no claim
#     quotes it, so un-confounding it is not this batch's purchase.
#   * 60 or 100 epochs.  57 epochs of headroom is an extrapolation from a Q4
#     velocity, and B0.3 exists precisely because extrapolations fail.  40 is
#     a 2x budget doubling with a 17-epoch margin.  If B0.3 passes cleanly at
#     40, the next rung is cheap and can be registered then.
#   * blk6.  Below its own rho_min in 9 of 9 ml5 arms.  A confound and no number.
#
# WHY cluster_b.  Account assignment is BY COMPARATOR (CORRECTIONS 46(6)).  The
# control arm (`cl5-*-cU-*`) is on cluster_b, as is the whole ml5/wc5 ladder.
#
# STRUCTURAL CHECKS BEFORE USING ANY NUMBER (Rule 4)
#   1. B0.1-B0.3 above, run not assumed, B0.3 FIRST, then B1.5, then B1
#   2. python3 analysis/c52_boxfree.py --selftest      (27/27)
#   3. python3 analysis/neff_instrument.py --selftest  (19/19)
#   4. python3 analysis/probe5_window.py --selftest    (41/41)
#   5. Window scan on every arm.  A 4000-record run has DIFFERENT absolute
#      windows from a 2000-record one; say which you mean, every time.
#
# USAGE
#   bash c52_budget_ladder.sh            # dry run: prints every sbatch line
#   bash c52_budget_ladder.sh --submit   # submits, ONLY if the guards below pass
# =============================================================================
set -u

WS=/cluster/account_b/metaopt                          # cluster_b
RUNNER=$WS/jobs/run_cifar.sh
HF=$WS/MetaOptimize/codes/Supervised_tasks/MetaOptimize/cifar10/Optimizers/HF.py
SAVE=$WS/runs/bl5
PARTS=gpu-short,gpu-l4-24g,gpu-2080ti-11g,gpu-mig-40g,gpu-a100-80g
USER_NAME=account_b
PEND_CAP=40
NJOBS=9
BOX=-30:0.0                                        # measured non-binding at 20ep
EPOCHS=40
SUBMIT=0
[ "${1:-}" = "--submit" ] && SUBMIT=1

echo "=== c52 BOX-FREE BUDGET LADDER + PROBE5 (cluster_b) ==="
echo "    BETA_CLIP=$BOX  epochs=$EPOCHS  control = cl5-*-cU-* at 20 epochs, n=3"

if ! grep -q PATCH_PROBE5 "$HF" 2>/dev/null; then
  echo "GUARD FAIL: PATCH_PROBE5 not present in $HF"; exit 1
fi
if ! grep -q PATCH_PROBE5_FIX "$HF" 2>/dev/null; then
  echo "GUARD FAIL: PATCH_PROBE5_FIX not present -- unfixed patch crashes at record 500"; exit 1
fi
if ! grep -q PATCH_CLIPCOUNT "$HF" 2>/dev/null; then
  echo "GUARD FAIL: PATCH_CLIPCOUNT not present -- B0.3's per-coordinate denominator"; exit 1
fi
echo "guard 1: PATCH_PROBE5 + PATCH_PROBE5_FIX + PATCH_CLIPCOUNT present  OK"

python3 -c "import py_compile; py_compile.compile('$HF', doraise=True)" 2>/dev/null || {
  echo "GUARD FAIL: $HF does not compile"; exit 1; }
echo "guard 2: HF.py compiles  OK"

# GUARD 3 -- "byte-matched except one field" is a CLAIM (the uc5 lesson, cycle 52).
# The control is cl5, and the ONLY field that may differ is --num-epochs.
CL5=$(dirname "$0")/c51_ceiling_ladder.sh
if [ -r "$CL5" ]; then
  for f in "ResNet18" "CIFAR10" "SGDm" "Lion" "1e-3"; do
    grep -q -- "$f" "$CL5" || { echo "GUARD FAIL: '$f' absent from the cl5 control"; exit 1; }
  done
  grep -q -- "--num-epochs 20" "$CL5" || {
    echo "GUARD FAIL: cl5 is not a 20-epoch batch -- the ladder has no lower rung"; exit 1; }
  echo "guard 3: cl5 control is R18/CIFAR10/SGDm/Lion/ms=1e-3 at 20 epochs  OK"
else
  echo "guard 3: c51_ceiling_ladder.sh not readable here -- SKIPPED (say so in FINDINGS)"
fi

FS=$(sshare -U -u "$USER_NAME" -n -o FairShare 2>/dev/null | tr -d ' ' | head -1)
PEND=$(squeue -h -u "$USER_NAME" -t PENDING 2>/dev/null | wc -l | tr -d ' ')
echo "guard 4: FairShare=${FS:-unknown} (informational), pending=$PEND, adding $NJOBS"
if [ "$SUBMIT" = "1" ]; then
  [ "$((PEND + NJOBS))" -le "$PEND_CAP" ] || {
    echo "ABORT: $PEND pending + $NJOBS would exceed the $PEND_CAP cap"; exit 1; }
fi

mkdir -p "$SAVE"
N=0
FAIL=0
for G in layerwise nodewise weightwise; do
  case $G in
    layerwise)  TAG=lay  ;;
    nodewise)   TAG=node ;;
    weightwise) TAG=w    ;;
  esac
  for S in 0 1 2; do
    RN="bl5-${TAG}-e${EPOCHS}-s${S}"
    PD="$SAVE/probe_${TAG}_e${EPOCHS}_s${S}"
    # --time=03:50:00, NOT 05:50:00.  `gpu-short` caps below 5h and rejects the
    # whole batch with "Requested time limit is invalid"; the first --submit of
    # this script lost all 9 jobs that way.  20 epochs takes 8-16 min at R18, so
    # 40 takes ~16-32 and 3h50 is a 7x margin.
    CMD=(sbatch --job-name="$RN" --partition="$PARTS" --time=03:50:00
      --export="ALL,AUGMENT=1,BETA_CLIP=$BOX,PROBE=5,PROBE5=1,PROBE5_WRITE_EVERY=500,PROBE_DIR=$PD"
      "$RUNNER"
      --optimizer HF --alg-base SGDm --momentum-param-base 0.99 --weight-decay-base 0.1
      --alg-meta Lion --momentum-param-meta 0.99 --Lion-beta2-meta 0.9 --weight-decay-meta 0
      --dataset CIFAR10 --NN-name ResNet18 --batch-size 100
      --max-time 999:00:00 --gamma 1 --meta-stepsize 1e-3 --alpha0 1e-3
      --num-epochs "$EPOCHS" --stepsize-groups "$G" --seed "$S"
      --save-directory "$SAVE" --run-name "$RN")
    # COUNT WHAT SLURM ACCEPTED, NOT WHAT WE TRIED.  The earlier version printed
    # "9 jobs (SUBMITTED)" while sbatch had rejected all 9 on the time limit.
    # A batch script that reports its intent instead of its outcome is how a
    # tick ends up scoring a pre-registration against an empty queue.
    if [ "$SUBMIT" = "1" ]; then
      if "${CMD[@]}" >/dev/null; then N=$((N+1)); else FAIL=$((FAIL+1)); fi
    else
      N=$((N+1)); printf '%s\n' "${CMD[*]}"
    fi
  done
done
echo "---- $N jobs ($( [ "$SUBMIT" = 1 ] && echo ACCEPTED BY SLURM || echo 'dry run, nothing submitted' )); $FAIL rejected ----"
[ "$FAIL" -gt 0 ] && echo "!!! $FAIL sbatch calls FAILED -- do not treat this batch as submitted"
echo "reduce with, IN THIS ORDER:"
echo "  1. python3 analysis/c52_boxfree.py                    # B0.3 BOX-FREE GATE -- FIRST"
echo "  2. (new) neff_instrument.py --window 0.25-0.5 ../probes_bl5   # B1.5 replication"
echo "  3. python3 analysis/neff_instrument.py ../probes_bl5  # B1 -- THE PRIMARY TEST"
echo "  4. python3 analysis/probe5_window.py ../probes_bl5    # B2 + B2.5 + window scan"
