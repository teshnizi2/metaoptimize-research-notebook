# ARGS-AUDIT — the duplicate-flag sweep of the whole corpus

Cycle 99. Zero GPU. Authority for this file: the runs' own `ARGS` lines on both clusters.
Supersedes nothing; **extends CORRECTIONS 125.4**, which ran the same sweep over the 2,181
*local* `.out` and left the ten flagged scripts unaudited. This closes that item.

**Rule under test — STANDING RULE 20.** A batch's science is what the runs' own `ARGS` line
says, never what the submission script's header says. `jobs/run_cifar.sh` echoes `ARGS: "$@"`
then calls `python -u train.py "$@"`; `argparse` keeps the **last** occurrence of a repeated
option, silently.

## 2. Every flag, not just `--alg-meta`

The corpus uses **23 distinct flags**, all in canonical `--long-form`:

`--Lion-beta2-base --Lion-beta2-meta --NN-name --alg-base --alg-meta --alpha0 --batch-size
--dataset --gamma --max-time --meta-stepsize --momentum-param-base --momentum-param-meta
--normalizer-param-base --normalizer-param-meta --num-epochs --optimizer --run-name
--save-directory --seed --stepsize-groups --weight-decay-base --weight-decay-meta`

Three ways a duplicate could have hidden from a naive scan were checked and **all three are
absent**:

| evasion | occurrences |
|---|---|
| `--flag=value` form (parses as one token) | **0 runs** |
| underscore spelling (`--alg_meta`) | **0 runs** |
| argparse prefix abbreviation collapsing two spellings onto one `dest` | **0** — no flag used is a prefix of another |

So a flag-name count is a sound duplicate test on this corpus.

### Flags that repeat, corpus-wide

| flag | runs affected | batches |
|---|---|---|
| `--alg-meta` | 36 | `ml2` 24, `sm3` 12 |
| `--weight-decay-meta` | 36 | `ml2` 24, `sm3` 12 |
| `--momentum-param-meta` | 12 | `ml2` (the `adam` half) |

**No other flag repeats in any run.** In particular `--alg-base`, `--stepsize-groups`,
`--meta-stepsize`, `--alpha0`, `--num-epochs`, `--seed` and `--normalizer-param-*` are
single-occurrence everywhere — the partition axis, the budget axis and the step-size axis were
never overwritten anywhere in the corpus.

## 4. The CSV never lied

Every one of the 2,113 CSV rows was reconciled field-by-field against its own run's `ARGS`
line, across **11 fields**: `network dataset batch_size granularity base meta meta_stepsize
alpha0 gamma seed epochs_requested`.

**Result: zero mismatches.**

The reason is worth recording, because it changes what "the void list" means:
`analysis/aggregate.py`'s `parse_args_line` builds a dict with `out[k] = v` in one forward
pass — **it is last-wins, exactly like argparse**. So the aggregator recorded what actually
ran. All 24 `ml2` rows already read `meta = Lion`.

> **The void is in the run NAMES and in the batch's declared design, never in the CSV values.**
> `ml2-adam-node-s0` is a row that correctly says `Lion`, sitting under a name that says
> `adam`. Any analysis keyed on the CSV columns is safe; any analysis keyed on the run-name
> substring, or on the batch's design as written up, is not.

The only apparent mismatches (161 `meta`, 144 `granularity`) are the sentinel `?` that
`aggregate.py` writes for baseline runs that legitimately pass no `--alg-meta` /
`--stepsize-groups` (`fxcos`, `i3a`, `bl`, `bx`, `SW`, `fx`, `i3c`, `g0*`, `f5cos`, `bg*`).
Not defects.

**Corollary for the pending `sm3` ingest:** running `aggregate.py` over `sm3`'s 12 `.out`
yields `meta = Lion` automatically. No hand-edit is needed and none should be made.

## 5. THE NEW DEFECT — `ml2`'s halves share their seeds

The 125.4 sweep asked "is a flag repeated?". This audit also asked the stronger question:

> **After last-wins resolution, do two differently-named runs in one batch describe the
> *same* experiment?**

Signature = effective `ARGS` (paths dropped) + the `ENV` line (`PROBE_DIR` dropped, it is an
output path) + `--seed`. Runs grouped; groups holding two or more *different* run names are
collapses.

| batch | runs | pairs | what collapsed |
|---|---|---|---|
| **`ml2`** | 24 | **12** | `ml2-adam-<g>-s<n>` ≡ `ml2-rms-<g>-s<n>` for all 4 granularities × 3 seeds |
| `h2` | 8 | 4 | `h2-blk6_s{0,1,2}` ≡ `h2-b-L0p1_s{0,1,2}`; `h2-lam01_s2` ≡ `h2-l-L0p1_s2` |
| `c100smoke` / `c100pin` | 4 | 2 | `…-layer` ≡ `…-probe` |

Nothing else in the corpus collapses. The many apparent collapses in an ARGS-only signature
(`ac`, `zsw`, `gp`, `sc`, `cs`, `r34r`, …) are arms separated by the **`ENV`** line
(`HIER`, `LAM`, `ETA_RATIO`, `BETA_CLIP`, `AUGMENT`), not by argparse — correctly designed.

### Why `ml2` matters and the others do not

`ml2-adam-node-s0` and `ml2-rms-node-s0` resolve to the **same command line, including
`--seed 0`**, and the same `ENV` (they differ only in `PROBE_DIR`, an output directory):

```
--optimizer HF --alg-base SGDm --momentum-param-base 0.99 --weight-decay-base 0.1
--alg-meta Adam --normalizer-param-meta 0.999 --momentum-param-meta 0.9 --weight-decay-meta 0
--alg-meta Lion --momentum-param-meta 0.99 --Lion-beta2-meta 0.9 --weight-decay-meta 0
--dataset CIFAR10 --NN-name ResNet18 --batch-size 100 --gamma 1 --meta-stepsize 1e-4
--alpha0 1e-3 --num-epochs 100 --stepsize-groups nodewise --seed 0 ...
```

So **`ml2` is not 6 seeds; it is 3 seeds, each run twice.** The two halves are *nondeterministic
reruns*, not independent replicates. `results/all_runs.csv` carries `dup_group = ""` and
`superseded = 0` on all 24 — the corpus's own duplicate machinery (populated for only 3 `a0`
rows) never saw them.

`h2` and `c100*` are the same shape but inert: `h2`'s `M0 shrink` is **withdrawn** in
`paper/DRAFT-v2.md` (§7 / M-table), and `c100smoke`/`c100pin` are 3-epoch smoke tests with empty
`plateau5` and `window_ok = 0`, excluded by STANDING RULE 21's filter.

### What it costs — re-derived from `plateau5`, not quoted

D = `chunk777 − nodewise`, G = `chunk2325 − nodewise1d`, unpaired, as the draft computes them.
The point estimates are **unchanged**; only the standard errors move.

| quantity | draft, "6 v 6" | honest — reruns averaged, 3 seeds | effect |
|---|---|---|---|
| D | **+0.456 ± 0.142, t 3.20** | **+0.456 ± 0.195, t 2.34** | se ×1.37, still resolved |
| G | **+0.173 ± 0.071, t 2.44** | **+0.173 ± 0.073, t 2.38** | se ×1.03, still resolved |
| D − G | +0.282 ± 0.159, t 1.77 | +0.282, t ≈ 1.9 | unresolved either way |

**Why the damage is small, and this is a real result rather than an excuse:** the corpus's
established METHODS finding is that **seed is null** (F 1.21, p 0.213). `ml2` reproduces it
from the inside — between-seed sd **0.179** vs pure run-to-run nondeterminism sd **0.183**,
a ratio of **0.98×**. When seed contributes no variance beyond nondeterminism, counting a
rerun as a seed costs little. G barely moves at all.

**A free by-product.** These 12 pairs are the cleanest **nondeterminism bound** in the corpus:
same code, same config, same seed, same batch, mean |Δ plateau5| **0.163 pp**, max **0.472 pp**.
That is a directly measured floor on any single run, and it is of the same order as
τ = 0.215 pp (§4.4) and as the batch-offset bound `sm3` supplies.

## 6. `sm3` — one correction to the salvage

`sm3` is confirmed **VOID AS DESIGNED** (the second-moment corner never ran; mechanism
candidate 8 is **UNTESTED, not refuted**) and salvageable as an `aw1` replicate. One claim in
`docs/STATUS.md` needs a word changed:

> **`sm3` is NOT "byte-identical" to `aw1`.** After last-wins, `sm3` still carries a residual
> `--normalizer-param-meta 0.999` that `aw1` does not. Every other effective flag matches at
> all four granularities.

The residual is **inert** — the runtime prints
`args_meta includes unnecessary attributes {'normalizer_param'}`, i.e. Lion ignores it — so
the salvage stands on the science. But the word "byte-identical" is false at the `ARGS` level,
and this is a **second, independent reason** to delete it beyond the β-box reason already
registered as R0 item 4.

## 9. The repair patch — WRITTEN, NOT APPLIED

`analysis/args_repair.py`. Dry-run by default; `--apply` required to write.

**No accuracy value changes. No row is deleted. No row is marked `superseded`** — both members
of every pair are real measurements.

| rows | column | from | to |
|---|---|---|---|
| 24 `ml2` | `dup_group` | `""` | `ml2-<gran>-s<seed>` (12 groups of 2) |
| 6 `h2` (`h2-blk6_s{0,1,2}`, `h2-b-L0p1_s{0,1,2}`) | `dup_group` | `""` | `h2-blocks-shrink0.1-s<seed>` |
| 2 `h2` (`h2-lam01_s2`, `h2-l-L0p1_s2`) | `dup_group` | `""` | `h2-layer-shrink0.1-s2` |
| 2 `c100smoke_{layer,probe}` | `dup_group` | `""` | `c100smoke-layer` |
| 2 `c100pin_{layer,probe}` | `dup_group` | `""` | `c100pin-layer` |

**36 rows change, one column, `dup_group`.** 2,077 rows untouched.

**The analysis rule the column then carries** — this is the part that actually protects a
headline: *any n, se or t computed over rows sharing a `dup_group` must average within the
group first, and count n as the number of distinct groups.* Applied to `ml2`, that rule
produces §5's honest column automatically.

Separately, and not part of this patch: **ingest `sm3`'s 12 rows** (2,113 → 2,125) by running
`aggregate.py` unedited. Its last-wins parser writes `meta = Lion` by itself (§4).

## 10. Reproducing this audit

```sh
# the flag sweep, on either cluster
python3 analysis/argsline_guard.py /cluster/account_a/metaopt/runs --quiet
python3 analysis/argsline_guard.py ~/metaopt/runs --quiet          # on cluster_b

# the collapse sweep and the CSV reconciliation
python3 analysis/args_repair.py --report
```

`analysis/argsline_guard.py` (STANDING RULE 20, already in the tree) is the flag test.
`analysis/args_repair.py --report` is the collapse test and the CSV reconciliation; it is the
check that would have caught `ml2`'s shared seeds.

Reproduced at write time — the guard's own numbers, which match this audit exactly:

| input | clean | repeated flag | no `ARGS` line |
|---|---|---|---|
| local `runs/` | 1,246 | 0 | 4 |
| local `runs_cluster_b/` | 895 | **24 (`ml2`)** | 0 |

`sm3`'s 12 show as repeated only on `cluster_a`, since the local mirror does not carry them.

**One caveat on the tool, for whoever next reruns it.** `argsline_guard.py`'s `collect_files`
globs `<dir>/*.out` and **does not recurse**. Twelve local `.out` live one level down, in
`runs/failed_hier_v1/` (7 × `hs`, 5 × `ha`), and the guard skips them silently — its totals
above are 1,250 top-level files, not the 1,262 that `find` reports. **This audit swept them;
all twelve are clean and none is in `all_runs.csv`.** But a future sweep that trusts the guard
alone will keep missing any run filed in a subdirectory. Either pass an explicit glob
(`analysis/argsline_guard.py 'runs/**/*.out'`) or make the directory walk recursive.
