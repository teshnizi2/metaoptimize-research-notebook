#!/bin/bash
# =============================================================================
# cDP1_depth_control.sh -- `cdep1`, THE IDENTITY-vs-DEPTH CONTROL FOR `ciso1`.
#   ONE SUBMISSION, 18 JOBS (6 arms x 3 seeds), 100 EPOCHS, SEEDS {24,25,26},
#   PROBE=100, PROBE_TENSOR=1 ON EVERY ARM.
#
# ACCOUNT: account_b (cluster_b).  WORKSPACE: /cluster/account_b/metaopt.  Nothing here
# touches the other account, nothing is submitted to `cluster_a`, and every guard
# and scancel line below is filtered on the `cdep1-` prefix alone.
#
# THE QUESTION.  `ciso1` (CORRECTIONS 187) moved three named 512-parameter
# layer4 BatchNorm SCALES (50 layer4.0.bn2.weight, 53 layer4.0.shortcut.1.weight,
# 59 layer4.1.bn2.weight) out of the shared step-size group and recovered the
# WHOLE scalar->layerwise gap (+46.9307 pp, +62.10 SE); its control isolated the
# layer-2 homologues and recovered nothing (-0.0633 pp).  `187.4` records the
# binding limitation: those two arms differ in tensor IDENTITY, network DEPTH
# and isolated NUMEL at once.  `cdep1` isolates three layer-4 512-parameter
# BatchNorm parameters containing NO carrier, at sizes [59,3] and isolated numel
# 1,536 -- matched to `ISO` on group sizes, isolated parameter count and depth.
#
# REGISTERED SCORER: analysis/cDP1_cdep1_depth_score.py, git-committed BEFORE
# this batch is submitted (STANDING RULE 21; the proof is the commit time
# against the earliest sacct Submit, stated in CORRECTIONS with the margin in
# seconds).  The hypothesis, both live accounts, every bar (in pp AND in SE from
# a noise floor RE-DERIVED at registration on the 2,761-row corpus with cdep1's
# own rows excluded from every reader), the partitions, the branch map, the
# floor/saturation registration and the point predictions are frozen there;
# --selftest re-derives every corpus premise AND, on this host, the ex-ante
# flip-share premise from `ciso1`'s own k01 probe records.
#
# THE DOCUMENTED SCORER INVOCATION -- no second argument to forget:
#     python3 analysis/cDP1_cdep1_depth_score.py <runsdir>
#
# -----------------------------------------------------------------------------
# THE ARMS (m = 2 group ORDER: the coarse group is beta[0], the isolated group
# beta[1]).  1-BASED indices, verified BY NAME on the live model by guard 4
# below, which prints the full manifest per arm.
#   k01     scalar                                   floor anchor, in batch
#   k62     layerwise                                ceiling anchor, in batch
#   ISO     sets:<59 others>/50,53,59    [59,3]      THE POSITIVE CONTROL,
#           re-run IN BATCH at fresh seeds.  BATCH is the unit of replication in
#           this campaign (F(62,85)=5.47) and SEED is null (F(11,1976)=0.152), so
#           reading DEPTH against ciso1's ISO would be a cross-batch contrast on
#           the campaign's largest variance component.  Cost of doing it right:
#           3 jobs, about 2.2 GPU-h.
#   DEPTH   sets:<59 others>/47,48,56    [59,3]      *** THE ARM ***
#           layer4.0.bn1.weight, layer4.0.bn1.bias, layer4.1.bn1.weight.
#           1,536 isolated parameters -- IDENTICAL to ISO on group sizes, on
#           isolated numel and on depth; every member 512-wide and in layer4;
#           NO carrier.  DISCLOSURE IT MUST CARRY: index 48 is a BatchNorm
#           BIAS, not a scale, because ResNet-18 has exactly FIVE BN scales in
#           layer4 (47, 50, 53, 56, 59), three of which ARE the carriers -- so a
#           class-matched, depth-matched, numel-matched, carrier-free TRIPLE
#           does not exist on this model.  Guard 4h proves that on the live
#           model rather than asserting it.
#   DEPTH2  sets:<60 others>/47,56       [60,2]      the class-pure variant:
#           the ONLY two non-carrier BN scales in layer4.  Matched on class and
#           depth, unmatched on count and numel (1,024).  It answers "the bias
#           member ruined the arm" IN BATCH instead of in prose.
#   ONE     sets:<61 others>/50          [61,1]      the arm that kills the
#           content-free rival H-BROKEN ("any partition other than ISO floors").
#           `164.6` killed cpr1's headline because exactly this rival was never
#           registered and its floored treatment arm could not be told from "it
#           died".  The modal predicted outcome here is a FLOORED DEPTH, so
#           without ONE the modal outcome is unreadable.  ONE rescued by
#           +41.4693 pp in ciso1 at a DIFFERENT set and a DIFFERENT size.
#
# The isolated group is written by NAME and the coarse group by INDEX RANGES, so
# an off-by-one in either half is a duplicate or a gap and PATCH_NAMESETS raises
# at parse time (guard 4 composes every arm on the live model before anything is
# submitted).  `187.4`'s DEPTH string was WRONG as first written (it listed 48
# on both sides of the `/`); every string below was RE-DERIVED here from the
# live 62-tensor manifest, not inherited, and guard 4 recomputes the complement
# from scratch.
#
# RULE 20.  Every value below is ONE shell token of [A-Za-z0-9_.,:/-].
# analysis/argsline_guard.py IS NOT EDITED.  BETA_CLIP, PROBE and PROBE_TENSOR
# are ENVIRONMENT variables; the first two are audited from the runner's ENV
# line, PROBE_TENSOR from the `PROBE_TENSOR: on` line the patch prints.
#
# PARTITIONS: composed by bin/_lib_guards.sh's slurm_parts_for_wall
# (CORRECTIONS 178); gpu-short is included at WALL=03:00:00 and the source-time
# hook aborts if PARTS/WALL disagree.  WALL is 1.9x ciso1's slowest run
# (95 min on a 2080ti node).
#
# COST.  ciso1 ran the same cell / horizon / shape: 15 jobs, 13.02 GPU-h by
# sacct Elapsed, median 43 min, slowest 95 min.  18 jobs at that median is
# about 15.6 GPU-h; the worst case (every job on a 2080ti node) is 28.5 GPU-h.
# Both are inside the ~30 GPU-h ceiling for this account's share.
#
# USAGE   bash bin/cDP1_depth_control.sh            # dry run, submits nothing
#         bash bin/cDP1_depth_control.sh --submit
