#!/bin/bash
# =============================================================================
# Cycle 71 -- THE 80-EPOCH BUDGET POINT, RE-RUN AT A LOWERED **FLOOR**.
# cluster_b.  12 jobs.  Tag `bf8-*`.  80 epochs.
#
# WHY THIS EXISTS.  `bd7-*` was supposed to be the third point of the N_eff/m
# budget curve (20 -> 40 -> 80).  It is **VOID** (CORRECTIONS 101.4):
#
#     D0.3 fails on 10 of 12 arms at the **LO** guard -- 37.11-41.86% of records,
#     100% of Q4.  The only two box-free arms are exactly the two that COLLAPSED
#     to 10.000 (D0.4 FAIL) and whose N_eff/m is UNRESOLVED.  No arm passes both
#     gates.
#
# `bd7` varied the **HI** ceiling (+2.0 vs +6.0) and held **LO = -30** fixed in
# both.  The wall that binds is the one the design held constant.  That is now
# STANDING RULE (18): *a box-free gate must be scored at BOTH guards, and a batch
# that varies one guard must assert the OTHER is non-binding AT ITS OWN BUDGET.*
#
# THE FLOOR IS SIZED FROM MEASUREMENT, NOT FROM AN EXTRAPOLATION.  beta_true_min
# descends almost exactly linearly in epochs, measured on br6 (40 ep) and bd7
# (80 ep), same instrument, same config:
#
#     epoch      10       20       40       first hits -30
#     br6      -11.7    -16.7    -26.7     never (min -24.95 to -26.74)
#     bd7      -11.7    -16.7    -26.5     record 4654-5031 = epoch 46.5-50.3
#
#   Rate: -0.49/epoch over 10->20, -0.505/epoch over 20->40.  Linear extrapolation
#   to 80 epochs gives ~ -47.
#
#   **BUT STANDING RULE (7)'s COROLLARY FORBIDS FUNDING A BATCH ON AN EXTRAPOLATED
#   HEADROOM IN EITHER DIRECTION.**  So the extrapolation is NOT used to pick one
#   "low enough" floor.  This batch runs **TWO FLOORS AND MEASURES** the
#   floor-dependence, exactly as `bd7` ran two ceilings -- but on the axis that
#   actually binds.  -60 sits ~13 log units below the projection and -90 ~43.
#
# THE LICENCE FOR COMPARING ACROSS FLOORS IS MEASURED, NOT ASSUMED.  A guard that
# never binds is not acting: br6 at 40 epochs is 0.00% occupancy at LO=-30 on
# 12/12 arms, so its trajectory is identical to what it would have been at any
# lower floor.  F0.5 re-tests that licence AT 80 EPOCHS rather than assuming it
# carries -- which is precisely the assumption bd7 made and lost.
#
# THE DESIGN.  Byte-identical to `bd7-*` except the CLIP:
#   R18/CIFAR-10, SGDm base, Lion meta, ms=1e-3, alpha0=1e-3, AUGMENT=1,
#   **80 epochs**, rungs w/node/lay, **LO in {-60, -90}** with **HI fixed at +2.0**,
#   seeds 0-1.  3 x 2 x 2 = 12 jobs.
#
#   HI IS FIXED AT +2.0 AND NOT VARIED, ON bd7's OWN EVIDENCE: bd7's HI=+6.0
#   weightwise arms COLLAPSED to 10.000 on 2 of 2 seeds while node/lay were
#   indifferent to the same change (92.112 vs 92.142, 91.025 vs 90.961).  The
#   ceiling ladder must go DOWN, not up -- bd7's own D0.4 branch says so.  Spending
#   the freed jobs on the floor axis is the correction, not a new question.
#
# PRE-REGISTERED PREDICTIONS -- score against these, not against what lands.
#
#   (F0) VALIDITY.  n_records == 8000 (PROBE=5 -> 100 records/epoch).  n_beta
#        byte-matches (w 11,173,962 / node 14,420 / lay 62) -- the partition is a
#        property of the NETWORK, so a mismatch means the network changed and the
#        batch is VOID.  beta moved, 12/12.
#
#   (F0.3) THE BOX-FREE GATE, SCORED FIRST, PER SEED, PER FLOOR, **AT BOTH
#        GUARDS** (STANDING RULE 18).  < 5% of records at LO **and** < 5% at HI.
#        **THE LO COLUMN IS THE ONE THAT MATTERS AND IT IS THE ONE bd7 FAILED.**
#        If an arm binds at LO even at -90, `first_lo` and its epoch IS the result:
#        beta is not confinable at this budget and the next batch is an `ms`
#        ladder, not a third floor.  Say that; do not report a number.
#
#   (F0.4) THE TRAINS-AT-ALL GATE, SCORED SECOND.  plateau5 > 40.0 and `collapsed`
#        false, per seed.  bd7's LO=-30 arms trained fine (90.2-92.2) apart from
#        the two HI=+6.0 collapses, so a failure here would be caused by the FLOOR,
#        which would itself be the result.  A lower floor permits alpha down to
#        e^-90 ~ 8e-40, i.e. a coordinate that is effectively frozen rather than
#        clipped -- that is the intended difference and is not a fault.
#
#   (F0.5) THE FLOOR-INVARIANCE GATE.  On any rung box-free at BOTH floors:
#        |N_eff/m(-60) - N_eff/m(-90)| <= the per-rung bar.
#        PASS -> the two floors POOL and the 80-epoch point is a budget point.
#        FAIL -> N_eff/m depends on the floor even where the floor never binds,
#                which invalidates every cross-box comparison the campaign has
#                made and is a BIGGER result than the budget curve.  Report it as
#                one; do not patch it.
#        BARS ARE MEASURED, NOT INVENTED -- br6, n=4, box-free 12/12, steady half,
#        variance instrument, 40 ep (the closest measured budget to 80):
#            w 0.02   node 0.06   lay 0.11        (max(0.02, 3 sd) per rung)
#
#   (F1) THE 80-EPOCH POINT -- what D1 was meant to be.  Registered branches,
#        unchanged from `bd7` so this is a re-run and not a new question:
#          (a) it keeps falling -> at realistic budgets per-weight meta-gradients
#              are nearly REDUNDANT; a stronger refutation of the sqrt(N) noise
#              model than the one we have, and a DIFFERENT sentence.
#          (b) it has a floor ~0.15 -> "at long budgets ~15%" is the sentence and
#              the 20-epoch range is a transient.
#          (c) it rebounds -> the 20->40 fall is not a trend at all.
#        **FINDINGS 55.6 WROTE A POST-HOC-DERIVED EXPECTATION BEFORE bd7 WAS
#        READABLE: weightwise at 80 epochs below 0.1509 and still falling.**  It
#        is still UNTESTED -- bd7's raw readings are measured on arms pinned to the
#        low wall for 100% of Q4 and were NOT quoted.  A confirmation here is a
#        REPLICATION of 55.6's curve and NEVER a discovery.
#
#   (F2) **THE SPAN BAND, OUT OF SAMPLE.  A DIRECTION IS REGISTERED, AND IT IS THIS
#        TICK'S OWN RESULT BEING PUT AT RISK.**  FINDINGS 71.7 established on eight
#        cells that the argmin of N_eff/m tracks ADAPTATION EXTENT (span), not
#        budget and not ms: `w` below span ~6.3, `node` in ~[8.9, 12.6], `w` above
#        ~17.5 (c55 3-rung/steady definition).  br6 at 40 ep / ms=1e-3 sits at
#        17.52 and reads `w`.  This batch is the SAME ms at DOUBLE the budget, so
#        its span must exceed 17.52 and it sits further ABOVE the band.
#        **PREDICTION: argmin = `w`, gap/SE >= 2.**
#        CONFIRMS -> 71.7's band survives an out-of-sample cell at a budget no cell
#             in its fit had, and the band gains the budget axis it currently lacks.
#        REFUTES (argmin = `node`) -> the band is NOT a function of span alone; the
#             eight-cell fit was confounded with budget after all, and 71.7 must be
#             restated with 101.9's "one scalar" claim WITHDRAWN.
#        This is registered BEFORE the data exists precisely so it cannot be fitted
#        afterwards, and it is registered AGAINST the tick that produced it.
#
# STRUCTURAL CHECKS BEFORE USING ANY NUMBER (Rule 4)
#   1. F0, F0.3, F0.4 above, run not assumed, PER JOB and IN THAT ORDER
#   2. python3 analysis/c71_bd7_bo7_score.py --selftest      (14/14)
#   3. python3 analysis/c55_neff_noise.py --selftest         (51/51)
#   4. Register the box in c55_neff_noise.BOXES BEFORE scoring -- the module skips
#      an unregistered root by design ("a guessed box is worse than no box").
#   5. Re-derive every number above from results/all_runs.csv and the probe dirs,
#      never quote it from this comment (STANDING RULE 1).
#
# USAGE
#   bash c71_floor_budget.sh            # dry run: prints every sbatch line
#   bash c71_floor_budget.sh --submit   # submits, ONLY if the guards pass
# =============================================================================
set -u

WS=/cluster/account_b/metaopt                          # cluster_b -- bd7's workspace
RUNNER=$WS/jobs/run_cifar.sh
HF=$WS/MetaOptimize/codes/Supervised_tasks/MetaOptimize/cifar10/Optimizers/HF.py
SAVE=$WS/runs/bf8
PARTS=gpu-short,gpu-l4-24g,gpu-2080ti-11g,gpu-mig-40g,gpu-a100-80g
USER_NAME=account_b
PEND_CAP=40
NJOBS=12
HI=2.0                         # FIXED -- bd7's HI=+6.0 collapsed weightwise 2/2
EPOCHS=80
MST=1e-3
WALL=03:50:00
SUBMIT=0
[ "${1:-}" = "--submit" ] && SUBMIT=1

echo "=== c71 bf8 -- the 80-epoch point, re-run at a LOWERED FLOOR (cluster_b) ==="
echo "    LO in {-60,-90}, HI fixed +2.0, ms=$MST, ${EPOCHS}ep, rungs w/node/lay, seeds 0-1"
echo "    bd7 was VOID: 10/12 arms bound at LO=-30 (37-42% of records, 100% of Q4)"
echo "    F2 registers a DIRECTION against this tick's own span band: argmin = w"
echo

# GUARD 1 -- the runner, the optimizer source, and the probe patches.
[ -r "$RUNNER" ] || { echo "GUARD FAIL: $RUNNER not readable"; exit 1; }
[ -r "$HF" ]     || { echo "GUARD FAIL: $HF not readable"; exit 1; }
for P in PATCH_PROBE5 PATCH_CLIP PATCH_CLIPCOUNT; do
  grep -q "$P" "$HF" || { echo "GUARD FAIL: $P not present in $HF"; exit 1; }
done
echo "guard 1: runner readable; PATCH_PROBE5 + PATCH_CLIP + PATCH_CLIPCOUNT present  OK"

python3 -c "import py_compile; py_compile.compile('$HF', doraise=True)" 2>/dev/null || {
  echo "GUARD FAIL: $HF does not compile"; exit 1; }
echo "guard 2: HF.py compiles  OK"

# GUARD 2b -- THE CLIP PARSER MUST ACCEPT THE FLOORS THIS BATCH USES.  A silent
# parse failure would run the batch UNCLIPPED and look like a box-free success.
python3 - "$HF" <<'PYEOF' || exit 1
import re, sys
src = open(sys.argv[1]).read()
m = re.search(r"_bc\.split\('?:'?\)", src) or re.search(r'_bc\.split\(":"\)', src)
assert m, "BETA_CLIP is not parsed by splitting on ':' -- the format assumed here is wrong"
assert "float(lo), float(hi)" in src.replace(" ", "").replace("float(lo),float(hi)", "float(lo), float(hi)") \
    or "float(lo)" in src, "BETA_CLIP bounds are not float()-parsed"
for v in ("-60.0", "-90.0", "2.0"):
    float(v)
print("guard 2b: BETA_CLIP parses as float(LO):float(HI); -60/-90 are representable  OK")
PYEOF

# GUARD 3 -- THE OPERATING POINT IS DIFFED AGAINST bd7 ITSELF, never asserted.
# The ONLY field that may differ from bd7 is the CLIP.  This is the uc5 lesson
# (CORRECTIONS 68/71) and it is what makes F1 a re-run rather than a new cell.
BD7=$(dirname "$0")/c54_budget_curve.sh
if [ -r "$BD7" ]; then
  for f in "ResNet18" "CIFAR10" "SGDm" "Lion" "--alpha0 1e-3" "--batch-size 100" \
           "--momentum-param-base 0.99" "--weight-decay-base 0.1" \
           "--momentum-param-meta 0.99" "--Lion-beta2-meta 0.9" "AUGMENT=1"; do
    grep -q -- "$f" "$BD7" || {
      echo "GUARD FAIL: '$f' absent from c54_budget_curve.sh -- bf8 is NOT bd7's"
      echo "            operating point, so F1 is not a re-run of D1.  STOP."; exit 1; }
  done
  grep -qE -- '(EPOCHS=80|--num-epochs 80)' "$BD7" || {
    echo "GUARD FAIL: bd7 is not an 80-epoch batch -- this is not its re-run"; exit 1; }
  grep -q -- "$MST" "$BD7" || { echo "GUARD FAIL: ms=$MST absent from bd7"; exit 1; }
  echo "guard 3: operating point byte-matches bd7 (11 fields + 80 ep + ms=$MST)  OK"
else
  echo "GUARD FAIL: c54_budget_curve.sh not readable -- cannot diff the operating point"; exit 1
fi

# GUARD 4 -- THE FLOOR ARITHMETIC, re-run rather than trusted to the comment.
python3 - <<'PYEOF' || exit 1
# beta_true_min descent, MEASURED on br6 (40 ep) and bd7 (80 ep) this cycle.
d10, d20, d40 = -11.7, -16.7, -26.6
r1 = (d20 - d10) / 10.0
r2 = (d40 - d20) / 20.0
assert -0.55 < r1 < -0.45 and -0.55 < r2 < -0.45, f"descent not ~-0.5/epoch: {r1}, {r2}"
proj80 = d40 + r2 * 40.0
assert -50 < proj80 < -44, f"80-epoch projection {proj80:.1f} is not near -47"
# BOTH floors must sit BELOW the projection, and the deeper one by a wide margin,
# because the projection is exactly what STANDING RULE (7) forbids relying on.
for lo, name in ((-60.0, "shallow"), (-90.0, "deep")):
    assert lo < proj80, f"{name} floor {lo} is ABOVE the projection {proj80:.1f}"
assert -60.0 - proj80 < -10, "the shallow floor has under 10 log units of margin"
# bd7's own bind epoch must be consistent with the descent, or the rate is wrong.
bind_ep = -30.0 / r2
assert 45 < bind_ep < 62, f"predicted bind epoch {bind_ep:.1f} vs measured 46.5-50.3"
# The two floors must be far enough apart to be a real dose on the invariance gate.
assert abs(-90.0 - (-60.0)) >= 30, "the two floors are not a dose"
print(f"guard 4: descent {r2:.3f}/epoch; 80-ep projection {proj80:.1f}; floors -60 "
      f"({-60.0 - proj80:.1f}) and -90 ({-90.0 - proj80:.1f}) both below it; bd7 bind "
      f"epoch predicted {bind_ep:.1f} vs measured 46.5-50.3  OK")
PYEOF

# GUARD 5 -- queue depth.  12 jobs is inside the ~20-job / 0.5%-RawUsage rule.
FS=$(sshare -U -u "$USER_NAME" -n -o FairShare 2>/dev/null | tr -d ' ' | head -1)
PEND=$(squeue -h -u "$USER_NAME" -t PENDING 2>/dev/null | wc -l | tr -d ' ')
echo "guard 5: FairShare=${FS:-unknown} (informational), pending=$PEND, adding $NJOBS"
if [ "$SUBMIT" = "1" ]; then
  [ "$((PEND + NJOBS))" -le "$PEND_CAP" ] || {
    echo "ABORT: $PEND pending + $NJOBS would exceed the $PEND_CAP cap"; exit 1; }
fi

# GUARD 6 -- the wall-clock request must fit the TIGHTEST partition in $PARTS.
# CORRECTIONS 71's silent-until-total failure: sbatch rejects against the SMALLEST
# MaxTime among requested partitions, so one over-long --time loses the WHOLE batch.
python3 - "$WALL" "$PARTS" <<'PYEOF' || exit 1
import subprocess, sys
def secs(t):
    d, _, rest = t.partition("-")
    if not rest: rest, d = d, "0"
    p = [int(x) for x in rest.split(":")]
    while len(p) < 3: p.insert(0, 0)
    return int(d) * 86400 + p[0] * 3600 + p[1] * 60 + p[2]
want, parts = sys.argv[1], sys.argv[2].split(",")
out = subprocess.run(["sinfo", "-h", "-o", "%P %l"], capture_output=True, text=True).stdout
lim = {}
for ln in out.split("\n"):
    f = ln.split()
    if len(f) == 2 and f[1] not in ("infinite", "n/a"):
        lim[f[0].rstrip("*")] = secs(f[1])
tight = [(p, lim[p]) for p in parts if p in lim]
if not tight:
    sys.exit("GUARD FAIL: sinfo returned no limit for any requested partition")
name, cap = min(tight, key=lambda kv: kv[1])
if secs(want) > cap:
    sys.exit(f"GUARD FAIL: --time={want} exceeds {name}'s MaxTime "
             f"({cap // 3600}:{cap % 3600 // 60:02d}) -- sbatch would reject the WHOLE batch")
print(f"guard 6: --time={want} fits the tightest partition {name} "
      f"({cap // 3600}:{cap % 3600 // 60:02d})  OK")
PYEOF

# GUARD 7 -- THROUGHPUT HEADROOM against bd7's OWN measured 80-epoch wallclock.
# THE CSV PATH IS PASSED IN FROM BASH, NOT DERIVED FROM __file__.  This block is
# fed to python on STDIN, so `__file__` is the literal string '<stdin>' and
# os.path.abspath('<stdin>') resolves against the CWD -- which silently pointed
# this guard at a STALE Aug-20 `~/metaopt/results/all_runs.csv` with no bd7 rows.
# It failed loudly here; the same bug in the other direction is a false PASS.
CSVP="$(cd "$(dirname "$0")/.." && pwd)/results/all_runs.csv"
[ -r "$CSVP" ] || { echo "GUARD FAIL: $CSVP not readable"; exit 1; }
python3 - "$WALL" "$CSVP" <<'PYEOF' || exit 1
import csv, sys
def secs(t):
    p = [int(x) for x in t.split(":")]
    return p[0] * 3600 + p[1] * 60 + p[2]
wall_min = secs(sys.argv[1]) / 60
csvp = sys.argv[2]
w = []
with open(csvp) as f:
    for r in csv.DictReader(f):
        if r["run"].startswith("bd7-") and r["wallclock_min"] and r["epochs_done"] == "80":
            w.append(float(r["wallclock_min"]))
if not w:
    sys.exit(f"GUARD FAIL: no completed 80-epoch bd7 wallclock in {csvp} to size against")
slow = max(w)
if slow > wall_min:
    sys.exit(f"GUARD FAIL: bd7's slowest 80-epoch run took {slow:.0f} min but --time is "
             f"{wall_min:.0f} min -- would truncate")
print(f"guard 7: bd7 80-epoch wallclock n={len(w)}, median {sorted(w)[len(w)//2]:.0f} min, "
      f"slowest {slow:.0f} min, against a {wall_min:.0f} min wall "
      f"({wall_min / slow:.1f}x headroom on the slowest)  OK")
PYEOF

mkdir -p "$SAVE"
N=0
FAIL=0
SGDM=(--optimizer HF --alg-base SGDm --momentum-param-base 0.99 --weight-decay-base 0.1
      --alg-meta Lion --momentum-param-meta 0.99 --Lion-beta2-meta 0.9 --weight-decay-meta 0)
for LO in -60 -90; do
  TAG=$([ "$LO" = "-60" ] && echo f60 || echo f90)
  for G in weightwise nodewise layerwise; do
    if   [ "$G" = weightwise ]; then SHORT=w
    elif [ "$G" = nodewise ];   then SHORT=node
    else                             SHORT=lay
    fi
    for S in 0 1; do
      RN="bf8-${SHORT}-${TAG}-s${S}"
      CMD=(sbatch --job-name="$RN" --partition="$PARTS" --gres=gpu:1 --cpus-per-task=6
        --mem=14G --time="$WALL" --nice=0
        --export="ALL,AUGMENT=1,BETA_CLIP=${LO}:${HI},PROBE=5,PROBE_DIR=$SAVE/probe_${SHORT}_${TAG}_s${S}"
        "$RUNNER" "${SGDM[@]}"
        --dataset CIFAR10 --NN-name ResNet18 --batch-size 100
        --max-time 999:00:00 --gamma 1 --meta-stepsize "$MST" --alpha0 1e-3
        --num-epochs "$EPOCHS" --stepsize-groups "$G" --seed "$S"
        --save-directory "$SAVE" --run-name "$RN")
      # COUNT WHAT SLURM ACCEPTED, NOT WHAT WE TRIED (CORRECTIONS 71).
      if [ "$SUBMIT" = "1" ]; then
        if "${CMD[@]}" >/dev/null; then N=$((N+1)); else FAIL=$((FAIL+1)); fi
      else
        N=$((N+1)); printf '%s\n' "${CMD[*]}"
      fi
    done
  done
done
echo "---- $N jobs ($( [ "$SUBMIT" = 1 ] && echo ACCEPTED BY SLURM || echo 'dry run, nothing submitted' )); $FAIL rejected ----"
[ "$N" = "$NJOBS" ] || echo "!!! expected $NJOBS jobs, built $N -- DO NOT TREAT AS SUBMITTED"
[ "$FAIL" -gt 0 ] && echo "!!! $FAIL sbatch calls FAILED -- do not treat this batch as submitted"
echo "reduce with, IN THIS ORDER:"
echo "  0. REGISTER THE BOX FIRST: add bf8:f60 -> (-60.0, 2.0) and bf8:f90 -> (-90.0, 2.0)"
echo "     to c55_neff_noise.BOXES with this script's path:line, or the root is SKIPPED."
echo "  1. F0    n_records==8000, n_beta byte-match, beta moved, PER JOB"
echo "  2. F0.3  BOX-FREE AT **BOTH** GUARDS, per seed per floor (STANDING RULE 18)."
echo "           The LO column is the one bd7 failed.  Binds at -90 too => report"
echo "           first_lo and its epoch; the next batch is an ms ladder, not a third floor."
echo "  3. F0.4  plateau5 > 40 and collapsed false, per seed"
echo "  4. F0.5  FLOOR-INVARIANCE on rungs box-free at BOTH floors; bars w .02 / node .06 / lay .11"
echo "  5. F1    the 80-epoch point: (a) keeps falling / (b) floor ~0.15 / (c) rebounds."
echo "           55.6's POST-HOC-DERIVED expectation (w below 0.1509, still falling) is"
echo "           STILL UNTESTED -- a confirmation REPLICATES it and is never a discovery."
echo "  6. F2    THE SPAN BAND OUT OF SAMPLE.  span must exceed br6's 17.52 (c55 defn)."
echo "           REGISTERED: argmin = w, gap/SE >= 2.  argmin = node REFUTES 71.7's band"
echo "           and WITHDRAWS 101.9's 'one scalar' claim."
