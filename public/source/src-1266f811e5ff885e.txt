#!/bin/bash
# =============================================================================
# Cycle 54 -- WHERE DOES N_eff/m GO?  THE 80-EPOCH BUDGET POINT.
# cluster_b.  12 jobs.  Tag `bd7-*`.
#
# THE OPEN QUESTION IT ANSWERS, and it is now the question the headline turns on.
#
#   CORRECTIONS 73 established that N_eff/m is NOT budget-stable, and cycle 54's
#   `br6-*` replicated it pre-registered, box-free on 12 of 12 seeds, at n=4:
#
#       rung        20 ep     40 ep     delta
#       lay        0.7262    0.6903    -0.036   stationary (and m=62, so a BOUND)
#       node       0.4056    0.2796    -0.126   drifting
#       w          0.5064    0.1508    -0.356   collapsing
#
#   The paper's headline -- "at the adapted operating point per-weight meta-
#   gradients carry 16%-55% of the independent information their count implies"
#   -- is therefore a **20-EPOCH** sentence (CORRECTIONS 73's quoting rule).  A
#   referee's first question is the obvious one: *where does it go?*  Nobody can
#   quote a budget-dependent headline without knowing whether the quantity has a
#   floor.  Two points do not distinguish these, and they say different things:
#
#     (a) it keeps falling      -> at realistic budgets per-weight meta-gradients
#                                  are nearly REDUNDANT.  A stronger refutation of
#                                  the sqrt(N) noise model than the one we have,
#                                  and a different sentence.
#     (b) it has a floor ~0.15  -> "at long budgets ~15%" is the sentence, and the
#                                  20-epoch range is a transient.
#     (c) it rebounds           -> the 20->40 fall is not a trend at all and
#                                  CORRECTIONS 73 needs a third scope.
#
#   80 epochs is the third point.  It is NOT funded past that: the 160-epoch point
#   is funded only after D0.3 scores, which is cycle 53's own discipline ("DO NOT
#   fund 80 epochs until C0.3 scores") applied to its successor.
#
# WHY THE CEILING IS AN EXPERIMENTAL VARIABLE HERE AND NOT A CHOSEN CONSTANT.
#   Measured travel in `br6` (this tick, 4000 records/run, per 10-epoch segment):
#
#       probe_w_c2_s1     -2.651 -> -2.431 -> -2.101 -> **+1.178**   (+3.279 in the last segment)
#       probe_node_c2_s3  -3.856 -> -3.312 -> -3.224 -> **+0.738**   (+3.962 in the last segment)
#       the other 10 runs DESCEND over the same segment (-0.03 to -0.56)
#
#   Max-beta travel is **bursty and seed-specific**: 2 of 12 runs move ~3-4 log
#   units in 10 epochs while the other 10 move backwards.  STANDING RULE (7)
#   COROLLARY says a monotone trend in a rate is not a property of the rate and
#   that no batch may be funded on an extrapolated headroom in EITHER direction.
#   So no single ceiling can be justified by extrapolation for a run twice as long.
#   The batch runs TWO ceilings and MEASURES the box-dependence instead.
#
#   The licence for comparing across box-free ceilings is itself measured, not
#   assumed: at 40 epochs `br6` (HI=+2.0) and `bl5` (HI=0.0) agree to **0.0009**
#   (lay 0.6903 vs 0.6912) and **0.0022** (node 0.2796 vs 0.2774) where both are
#   box-free.  D0.5 below re-tests that licence at 80 epochs rather than assuming
#   it carries.
#
# THE DESIGN.  Byte-identical to `br6-*` except EPOCHS and BETA_CLIP:
#   R18/CIFAR-10, SGDm base, Lion meta, ms=1e-3, alpha0=1e-3, AUGMENT=1,
#   **80 epochs**, rungs w/node/lay, **HI in {2.0, 6.0}** with LO fixed at -30,
#   seeds 0-1.  3 x 2 x 2 = 12 jobs.
#
# PRE-REGISTERED PREDICTIONS -- score against these, not against what lands.
#
#   (D0) VALIDITY.  n_records == 8000 (PROBE=5 -> 100 records/epoch, verified on
#        br6: 40 ep -> 4000).  n_beta byte-matches (w 11,173,962 / node 14,420 /
#        lay 62) -- the partition is a property of the NETWORK, so a mismatch
#        means the network changed and the batch is VOID.  beta moved, 12/12.
#
#   (D0.3) THE BOX-FREE GATE, SCORED FIRST, PER SEED, PER CEILING (STANDING RULE 8).
#        < 5% of records at either guard on EVERY seed, from beta_true_min/max AND
#        PATCH_CLIPCOUNT's per-coordinate counts.
#        **HI=+2.0 IS NOT EXPECTED TO PASS TRIVIALLY** and is not there to: br6
#        already reached +1.178 at 40 epochs, so this rung is a genuine test of
#        when the box becomes unavoidable.  If an arm binds, `first_hi` and its
#        epoch IS the result -- with cycle 53's HI=0.0 bind at epoch 30.4 this
#        builds a THREE-point curve of bind-budget against ceiling.  A bound arm's
#        D1 is UNINTERPRETABLE AT THAT CEILING; the HI=+6.0 arm may still carry it.
#
#   (D0.4) THE STABILITY GATE, SCORED SECOND.  plateau > 40.0 and `collapsed`
#        false, per seed.  HI=+6.0 permits alpha up to e^6 = 403.  br6's C0.4
#        showed the ceiling is not load-bearing at +2.0 (plateau moved +0.068 /
#        -0.122 / +0.028 pp against a 2.0 pp bar), but that is NOT evidence about
#        +6.0.  A failure here voids the +6.0 arm and says the ladder must go DOWN,
#        not up -- that is a result about the box, not about the budget.
#
#   (D0.5) THE CEILING-INVARIANCE GATE, and it is new.  On any rung where BOTH
#        ceilings are box-free: |N_eff/m(+2.0) - N_eff/m(+6.0)| <= the per-rung bar
#        below.
#        PASS -> the two ceilings may be POOLED and the budget curve is a budget
#                curve.
#        FAIL -> N_eff/m depends on the box even where the box never binds.  That
#                would invalidate every cross-ceiling comparison this campaign has
#                made, INCLUDING this tick's C1 and C2, and it is a bigger result
#                than the budget curve.  Report it as one; do not patch it.
#
#   THE BARS ARE PER RUNG AND ARE MEASURED, NOT INVENTED.  Per-seed sd of N_eff/m
#   at THIS batch's budget, from br6 (n=4, box-free 12/12, steady half, variance
#   instrument, 40 ep) -- the closest measured budget to 80:
#
#       rung    per-seed sd    3 sd     bar used = max(0.02, 3 sd)
#       w           0.0035    0.0105    **0.02**
#       node        0.0196    0.0588    **0.06**
#       lay         0.0361    0.1083    **0.11**
#
#   THE NOISE IS BUDGET-DEPENDENT, WHICH IS WHY THE BAR MUST BE TOO.  Measured at
#   20 epochs on `cl5-*-cU-*` (n=3, same instrument, same window):
#
#       rung    sd @ 20 ep    sd @ 40 ep    ratio
#       w          0.0377        0.0035      10.8x
#       node       0.0492        0.0196       2.5x
#       lay        0.0227        0.0361       0.6x
#
#   Weightwise N_eff/m becomes an order of magnitude MORE reproducible across seeds
#   as the budget grows, at the same time as its mean collapses 0.5064 -> 0.1508.
#   At 20 epochs the seeds disagree by ~7% of the value; at 40 epochs by ~2%.
#   (Recorded as FINDINGS 54.x; it is a by-product of setting this bar, not a
#   result this batch tests.)
#
#   NO PAST VERDICT CHANGES UNDER THESE BARS -- CHECKED EXPLICITLY, NOT ASSUMED.
#   The campaign's standing +-0.10 bar came from a BOX-sensitivity measurement at
#   weightwise (+-0.038, CORRECTIONS 62) and has been applied to all three rungs at
#   all budgets since.  Every gate it has decided was re-read against the measured
#   sd at ITS OWN budget:
#     * cycle-52's cross-box span 0.076 at 20 ep = **2.0 sd** (w), 1.5 sd (node),
#       3.3 sd (lay).  The +-0.10 bar was ~2.7 sd there -- appropriate.
#       **CORRECTIONS 68's box conclusion STANDS and is not re-opened.**
#     * C2 layerwise at 40 ep: -0.0359 = **1.0 sd**.  Passes either bar, and was
#       already reported as a BOUND rather than an absence, which is what 1.0 sd
#       licenses.
#     * C2 nodewise at 40 ep: -0.126 = **6.4 sd**.  C1 weightwise: -0.356 = ~9 sd
#       against the pooled 20/40 sd.  Both survive any bar.
#   So nothing is re-derived.  What is NOT true is that +-0.10 is a bar: at 40-epoch
#   weightwise it is ~29 sd, and this batch does not inherit it.  See STANDING RULE (9).
#   CAVEAT, stated in advance: an sd from n=4 carries ~40% uncertainty of its own,
#   which is why each bar is FLOORED at 0.02 rather than used raw; and the 80-epoch
#   sd is not yet measured, so these bars are imported from 40 and D1 reports the
#   80-epoch sd alongside its verdict.
#
#   (D1) THE PRIMARY TEST -- WHERE DOES WEIGHTWISE GO?  N_eff/m, weightwise,
#        VARIANCE instrument, STEADY half, against 40 ep = 0.1508.
#        **NO DIRECTION IS REGISTERED, and that is deliberate.**  The only basis
#        for predicting one is the 20->40 fall itself, and STANDING RULE (7)
#        COROLLARY exists precisely to stop this campaign extrapolating a rate onto
#        a segment it was not measured on.  The three branches are registered with
#        bars instead, and exactly one can fire:
#          (a) CONTINUES TO FALL:  <= 0.13  (0.1508 - 0.02, the per-rung bar)
#              -> the retained fraction is not bounded away from zero at reachable
#                 budgets.  The headline must carry a budget AND the paper must say
#                 the fraction shrinks with training rather than sitting at a value.
#          (b) FLOOR:              within +-0.02 of 0.1508
#              -> the 20->40 fall was a transient approach to a floor near 0.15;
#                 "at long budgets ~15%" becomes the quotable sentence.
#          (c) REBOUND:            >= 0.17
#              -> non-monotone in budget.  The 20->40 fall is not a trend, and
#                 CORRECTIONS 73's quoting rule needs a third scope, not a tweak.
#
#   (D2) THE GRANULARITY CONTRAST -- the independent half, and it replicates a
#        prediction that has now passed twice (bl5, br6).
#        Registered: **layerwise stays stationary** (within 0.11 of 0.6903) while
#        **nodewise continues to fall** (< 0.2796 - 0.06 = 0.22).
#        REFUTATION: layerwise moves MORE than nodewise in |delta|.
#          -> budget-robustness is not granularity-dependent after all and
#             CORRECTIONS 73's central claim is wrong.
#        The layerwise rung is reported as a **BOUND, never an absence**: m=62
#        against rho_min ~9.5e-04 is marginal, exactly as C2 recorded.
#
#   (D3) ACCURACY, reported regardless and NOT a test.  80 epochs is still far
#        short of the 100/300-epoch baseline comparisons, and ms/alpha0 are the
#        ladder's, so no plateau here may be set against the AdamW+cosine 94.24.
#
#   RESOLUTION, per CORRECTIONS 33, computed BEFORE submission.  rho_min falls as
#   T grows, so 8000 records can only IMPROVE on br6's 4000, where all 12 arms
#   read resolved=True:
#       weightwise  RESOLVES comfortably (m = 1.1e7)
#       nodewise    RESOLVES             (m = 14,420)
#       layerwise   MARGINAL at m=62 -- as at every budget.  D2's layerwise leg is
#                   a BOUND and is written as one.
#
# NOT INCLUDED, deliberately:
#   * 160 epochs.  Funded only after D0.3 scores -- +6.0 is an untested ceiling and
#     funding a 4x budget on it is the error CORRECTIONS 72 was written about.
#   * Other families / datasets.  The budget axis is R18/CIFAR-10 throughout and a
#     second family would confound budget with family at n=2.
#   * A third seed.  n=2 per (rung, ceiling) buys D1 against a 0.02 bar at 0.0035
#     measured sd; if any rung comes back inside its bar the third seed is bought
#     then, the ns5 -> ns6 pattern that worked.
#   * An ms axis.  One variable at a time; ms is held at 1e-3 so a D1 move is
#     attributable to the budget.
#
# WHY cluster_b.  Its comparators `br6-*` and `bl5-*` are both there, so
# CORRECTIONS 46(6)'s by-comparator rule is honoured rather than broken.
#
# STRUCTURAL CHECKS BEFORE USING ANY NUMBER (Rule 4)
#   1. D0, D0.3, D0.4 above, run not assumed, D0.3 FIRST and PER SEED
#   2. python3 analysis/c54_score.py --selftest        (12/12)
#   3. python3 analysis/neff_instrument.py --selftest  (23/23)
#   4. python3 analysis/probe5_window.py --selftest    (41/41)
#   5. Window scan on every arm.
#
# USAGE
#   bash c54_budget_curve.sh            # dry run: prints every sbatch line
#   bash c54_budget_curve.sh --submit   # submits, ONLY if the guards pass
# =============================================================================
set -u

WS=/cluster/account_b/metaopt                          # cluster_b
RUNNER=$WS/jobs/run_cifar.sh
HF=$WS/MetaOptimize/codes/Supervised_tasks/MetaOptimize/cifar10/Optimizers/HF.py
SAVE=$WS/runs/bd7
PARTS=gpu-short,gpu-l4-24g,gpu-2080ti-11g,gpu-mig-40g,gpu-a100-80g
USER_NAME=account_b
PEND_CAP=40
NJOBS=12
EPOCHS=80
WALL=03:50:00
SUBMIT=0
[ "${1:-}" = "--submit" ] && SUBMIT=1

echo "=== c54 BUDGET CURVE: the 80-epoch point, ceiling as a VARIABLE (cluster_b) ==="
echo "    epochs=$EPOCHS  HI in {2.0, 6.0}  seeds 0-1  controls = cl5-cU (20ep), br6/bl5 (40ep)"

for P in PATCH_PROBE5 PATCH_PROBE5_FIX PATCH_CLIPCOUNT; do
  grep -q "$P" "$HF" 2>/dev/null || { echo "GUARD FAIL: $P not present in $HF"; exit 1; }
done
echo "guard 1: PATCH_PROBE5 + PATCH_PROBE5_FIX + PATCH_CLIPCOUNT present  OK"

python3 -c "import py_compile; py_compile.compile('$HF', doraise=True)" 2>/dev/null || {
  echo "GUARD FAIL: $HF does not compile"; exit 1; }
echo "guard 2: HF.py compiles  OK"

# GUARD 3 -- "byte-identical to br6 except EPOCHS and BETA_CLIP" is a CLAIM and is
# DIFFED against br6 itself, never asserted (the uc5 lesson, CORRECTIONS 71).
BR6=$(dirname "$0")/c53_budget_replication.sh
if [ -r "$BR6" ]; then
  for f in "ResNet18" "CIFAR10" "SGDm" "Lion" "--meta-stepsize 1e-3" "--alpha0 1e-3" \
           "--momentum-param-base 0.99" "--Lion-beta2-meta 0.9" "--batch-size 100"; do
    grep -q -- "$f" "$BR6" || { echo "GUARD FAIL: '$f' absent from the br6 control"; exit 1; }
  done
  grep -q -- 'EPOCHS=40' "$BR6" || {
    echo "GUARD FAIL: br6 is not a 40-epoch batch -- the budget contrast is not what it claims"; exit 1; }
  grep -q -- 'BOX=-30:2.0' "$BR6" || {
    echo "GUARD FAIL: br6's box is not -30:2.0 -- the ceiling continuity claim is wrong"; exit 1; }
  echo "guard 3: br6 control is R18/CIFAR10/SGDm/Lion/ms=1e-3 at 40 epochs, BOX=-30:2.0  OK"
else
  echo "GUARD FAIL: c53_budget_replication.sh not readable -- cannot diff the claim"; exit 1
fi

# GUARD 4 -- the ceilings must BRACKET the measured 40-epoch maximum, or this is
# not a ceiling ladder.  br6's largest observed beta_true_max was +1.178.
python3 - <<'PYEOF' || exit 1
lo_ceiling, hi_ceiling = 2.0, 6.0
measured_max_40ep = 1.178          # br6 probe_w_c2_s1, beta_true_max at record 4000
assert lo_ceiling > measured_max_40ep, "the low ceiling is not above the measured 40-epoch max"
assert hi_ceiling > lo_ceiling, "the ladder is not ordered"
print(f"guard 4: ceilings {lo_ceiling:+.1f} / {hi_ceiling:+.1f} bracket the MEASURED "
      f"40-epoch max {measured_max_40ep:+.3f} by {lo_ceiling - measured_max_40ep:.3f} "
      f"and {hi_ceiling - measured_max_40ep:.3f} log units  OK")
PYEOF

# GUARD 6 -- THE WALL-CLOCK REQUEST MUST FIT THE TIGHTEST PARTITION IN $PARTS.
# This is the CORRECTIONS 71 failure mode and it is silent-until-total: sbatch
# rejects the request against the SMALLEST MaxTime among the requested
# partitions, so one over-long --time loses all 12 jobs.  This batch doubles the
# budget, so the wall clock had to change and the guard is read from `sinfo`
# LIVE rather than from a comment that was true for a 40-epoch batch.
python3 - "$WALL" "$PARTS" <<'PYEOF' || exit 1
import subprocess, sys
def secs(t):
    d, _, rest = t.partition("-")
    if not rest: rest, d = d, "0"
    p = [int(x) for x in rest.split(":")]
    while len(p) < 3: p.insert(0, 0)
    return int(d) * 86400 + p[0] * 3600 + p[1] * 60 + p[2]
want, parts = sys.argv[1], sys.argv[2].split(",")
out = subprocess.run(["sinfo", "-h", "-o", "%P %l"], capture_output=True, text=True).stdout
lim = {}
for ln in out.split("\n"):
    f = ln.split()
    if len(f) == 2 and f[1] not in ("infinite", "n/a"):
        lim[f[0].rstrip("*")] = secs(f[1])
tight = [(p, lim[p]) for p in parts if p in lim]
if not tight:
    sys.exit("GUARD FAIL: sinfo returned no limit for any requested partition")
name, cap = min(tight, key=lambda kv: kv[1])
if secs(want) > cap:
    sys.exit(f"GUARD FAIL: --time={want} exceeds {name}'s MaxTime "
             f"({cap // 3600}:{cap % 3600 // 60:02d}) -- sbatch would reject the WHOLE batch")
print(f"guard 6: --time={want} fits the tightest partition {name} "
      f"({cap // 3600}:{cap % 3600 // 60:02d})  OK")
PYEOF

FS=$(sshare -U -u "$USER_NAME" -n -o FairShare 2>/dev/null | tr -d ' ' | head -1)
PEND=$(squeue -h -u "$USER_NAME" -t PENDING 2>/dev/null | wc -l | tr -d ' ')
echo "guard 5: FairShare=${FS:-unknown} (informational), pending=$PEND, adding $NJOBS"
if [ "$SUBMIT" = "1" ]; then
  [ "$((PEND + NJOBS))" -le "$PEND_CAP" ] || {
    echo "ABORT: $PEND pending + $NJOBS would exceed the $PEND_CAP cap"; exit 1; }
fi

mkdir -p "$SAVE"
N=0
FAIL=0
for G in layerwise nodewise weightwise; do
  case $G in
    layerwise)  TAG=lay  ;;
    nodewise)   TAG=node ;;
    weightwise) TAG=w    ;;
  esac
  for C in 2.0 6.0; do
    case $C in
      2.0) CTAG=c2 ;;
      6.0) CTAG=c6 ;;
    esac
    BOX="-30:$C"
    for S in 0 1; do
      RN="bd7-${TAG}-${CTAG}-s${S}"
      PD="$SAVE/probe_${TAG}_${CTAG}_s${S}"
      # $WALL is checked against the LIVE gpu-short cap by guard 6 below, not
      # guessed.  This batch was first written with --time=05:50:00, which
      # gpu-short (MaxTime 4:00:00) would have rejected -- and a rejection there
      # takes the WHOLE batch with "Requested time limit is invalid"
      # (CORRECTIONS 71).  40 epochs took 13-18 min in br6 and up to 35 min in
      # bl5, so 80 epochs is ~26-70 min and 03:50:00 is a 3.3x worst-case margin
      # while keeping all five partitions usable.
      CMD=(sbatch --job-name="$RN" --partition="$PARTS" --time="$WALL"
        --export="ALL,AUGMENT=1,BETA_CLIP=$BOX,PROBE=5,PROBE5=1,PROBE5_WRITE_EVERY=500,PROBE_DIR=$PD"
        "$RUNNER"
        --optimizer HF --alg-base SGDm --momentum-param-base 0.99 --weight-decay-base 0.1
        --alg-meta Lion --momentum-param-meta 0.99 --Lion-beta2-meta 0.9 --weight-decay-meta 0
        --dataset CIFAR10 --NN-name ResNet18 --batch-size 100
        --max-time 999:00:00 --gamma 1 --meta-stepsize 1e-3 --alpha0 1e-3
        --num-epochs "$EPOCHS" --stepsize-groups "$G" --seed "$S"
        --save-directory "$SAVE" --run-name "$RN")
      # COUNT WHAT SLURM ACCEPTED, NOT WHAT WE TRIED (CORRECTIONS 71).
      if [ "$SUBMIT" = "1" ]; then
        if "${CMD[@]}" >/dev/null; then N=$((N+1)); else FAIL=$((FAIL+1)); fi
      else
        N=$((N+1)); printf '%s\n' "${CMD[*]}"
      fi
    done
  done
done
echo "---- $N jobs ($( [ "$SUBMIT" = 1 ] && echo ACCEPTED BY SLURM || echo 'dry run, nothing submitted' )); $FAIL rejected ----"
[ "$FAIL" -gt 0 ] && echo "!!! $FAIL sbatch calls FAILED -- do not treat this batch as submitted"
echo "reduce with, IN THIS ORDER:"
echo "  1. D0.3 PER SEED PER CEILING  -- the box-free gate, on ../probes_bd7"
echo "  2. D0.4 stability, then D0.5 CEILING-INVARIANCE (pool only if it passes)"
echo "  3. D1  neff_instrument.py ../probes_bd7   # branches (a)/(b)/(c), no direction registered"
echo "  4. D2  the lay-vs-node contrast; report layerwise as a BOUND"
echo "  5. Window scan: probe5_window.py ../probes_bd7"
