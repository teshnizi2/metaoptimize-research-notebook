# c83_gen_r34_merged.sh -- `g3m`, THE ResNet34 GENERALISATION OF THE TAIL
# PRESCRIPTION.  D AND G IN **ONE** BATCH, AT **ONE** META-STEPSIZE, n=9.
#
# 36 jobs: {nodewise, chunk835, nodewise1d, chunk2500} x seeds 0-8, ms=1e-4,
# ResNet34/CIFAR-10, 100 ep, AUGMENT=1, SGDm+Lion, alpha0=1e-3, BETA_CLIP=-15:-2.3026,
# PROBE=5 (occupancy only).  cluster_a ONLY (needs PATCH_CHUNKWISE/PATCH_NODEBN).
#
# -----------------------------------------------------------------------------
# THIS FILE SUPERSEDES TWO EARLIER, DELETED SCRIPTS.  READ THIS FIRST.
# -----------------------------------------------------------------------------
# cycle 83 first registered the ResNet34 generalisation as TWO batches:
#     bin/c83_gen_r34_dleg.sh  (`g3d`)  D leg: {nodewise, chunk835} x 3 ms x 3 seeds
#     bin/c83_gen_r34_tail.sh  (`g34`)  G leg: {nodewise1d, chunk2500} x 9 seeds,
#                                       at an ms DERIVED from g3d's argmax
# Adversarial review killed that design on TWO fatal grounds and both files are
# DELETED.  The reasons are recorded here because they are the reason this file
# exists in the shape it does:
#
#   (F1) THE MECHANISM TEST WAS DESIGNED CROSS-BATCH AND CROSS-ms.  The paper's
#        load-bearing sentence is not "chunk beats nodewise"; it is "D is large
#        AND G is null -- the whole gap lives in the size-1 tail".  On ResNet18
#        that comparison is WITHIN ONE BATCH: cc1 is 12 runs, FOUR arms
#        (chunk777, nodewise, chunk2325, nodewise1d), ONE ms, ONE box,
#        jobs 4715633-4715644.  Splitting it across g3d and g34 put the campaign's
#        own measured batch random effect (sd_batch ~ 0.21 pp, F(62,85)=5.47,
#        p=6.9e-13 -- STANDING RULE 14) INSIDE the D-minus-G contrast:
#            se(D-G) = sqrt(se_D^2 + se_G^2 + 2*sd_batch^2) = 0.33 pp,
#        so a true D-G of +0.5 would have landed at t=1.5.  The ResNet18 original,
#        within-batch, reads D-G = 0.727-0.011 = 0.716 at t=2.9.  The two-batch
#        replication would have had roughly HALF the power of the thing it
#        replicates, for the SAME 36 jobs.  **THIS BATCH IS cc1-SHAPED: four arms,
#        one ms, one box, one submission.  The batch offset cancels by
#        construction and never enters D, G or D-G.**
#
#   (F2) THE ms WAS CHOSEN BY A GUARD WITH NO BOX CHECK.  g34 derived its ms from
#        g3d's nodewise argmax.  ResNet18's nodewise argmax is 3e-4 -- the rung at
#        which ar1 bound on the floor 12/12 -- and g34's own scorer VOIDS on box
#        binding.  The modal outcome of the design was 18 jobs returning VOID.
#        **THIS BATCH PINS ms=1e-4 AND SAYS WHY IN THE OPEN (below).**
#
# -----------------------------------------------------------------------------
# THE PRE-REGISTRATION
# -----------------------------------------------------------------------------
#
# THE QUESTION.  The campaign's central surviving sentence is the TAIL
# PRESCRIPTION: at a MATCHED GROUP COUNT a uniform within-tensor chunking beats
# the architecture-aligned nodewise partition (D > 0), and the whole gap lives in
# the degenerate size-1 tail -- remove the tail and the gap vanishes (G = 0).
# Every reading of both legs is ResNet18 / CIFAR-10.  D, re-derived from
# results/all_runs.csv at write time (plateau5, never quoted from prose):
#     mm1  D = chunk777 - nodewise   +0.485  se 0.161  t 3.01   ms=1e-4
#     pp1  D                          +0.581  se 0.141  t 4.11   ms=1e-4
#     cc1  D                          +0.727  se 0.200  t 3.63   ms=1e-4
#     ar1  D                          +0.697  se 0.118  t 5.90   ms=3e-4 (LO-bound 12/12)
#     fa1  D                          +0.629  se 0.123  t 5.11   ms=3e-4, box -25:-2.3026
#   ms=1e-4 inverse-variance pool (mm1/pp1/cc1) = +0.5805 +- 0.0939, Q 0.88 on 2 df.
# And G, the tail-removed leg at an EXACT count match on ResNet18:
#     bn1  G = chunk2325 - nodewise1d  +0.295  se 0.048
#     ar1  G                           -0.139  se 0.072
#     cc1  G                           +0.011  se 0.147  t 0.08   <-- the anchor
#     fa1  G                           -0.001  se 0.076
#   The four R18 G readings are HETEROGENEOUS (Q = 26.2 on 2 df, p 2e-6, re-derived
#   at write time) and this batch REFUSES to pool them.  cc1 is the anchor because
#   it is the EXACT-count reading at the same ms and box as this batch.
#
# PREDICTED OUTCOME, STATED BEFORE THE DATA.  D_r34 in [+0.3, +0.8] and G_r34 in
#   [-0.15, +0.15].  ResNet34 carries the structure in the same proportion:
#   17,034 of 25,556 nodewise groups are size-1 (66.65% of m, covering 0.0800% of
#   the weights) against ResNet18's 9,610 of 14,420 (66.64%, 0.0860%).  f = 2/3 is
#   a structural constant of the conv->BN idiom (cycle 82).
#   **IF THE STRUCTURE IS IDENTICAL AND D IS NOT, THE STRUCTURAL ATTRIBUTION IS
#   WRONG.  That is the point of the batch.**
#
# REFUTATION CONDITIONS, FIXED HERE, BOTH LEGS.
#   H1 (D):  D_r34 in [-0.15,+0.15] (NULL) or <= -0.30 (REVERSES) **and**
#            separated from the R18 ms=1e-4 pool at |t| >= 2.  Either branch means
#            the tail prescription is a ResNet18/CIFAR-10 curiosity and the
#            paper's central sentence must be rescoped in the TITLE.
#   H2 (G):  "THE NULL REPLICATES" may be DECLARED only if a TOST at
#            delta = +-0.30 pp passes at alpha=0.05.  delta is 0.30 and NOT 0.15
#            because a TOST at 0.15 is arithmetically unreachable at any n this
#            campaign can afford: at the planning sd it needs |G| < 0.007.
#            If |G| >= +0.30 with |t| >= 2 vs cc1, the mechanism claim
#            ("the gap lives entirely in the size-1 tail") is REFUTED on R34.
#   H3 (D-G): the mechanism contrast, WITHIN-BATCH, no cross-batch floor.
#            R18/cc1 reads D-G = +0.716.  H3 CONFIRMS if D-G >= +0.30 at |t| >= 2.
#
# -----------------------------------------------------------------------------
# WHY n=9 PER ARM, AND WHY THE PLANNING sd IS **NOT** ResNet34's
# -----------------------------------------------------------------------------
#   The deleted g3d sized itself on ResNet34's own within-cell sd, median 0.156 pp.
#   That is measured on LAYERWISE (m=37) and SCALAR (m=1) cells -- ARMS THIS BATCH
#   DOES NOT RUN.  There is no within-architecture evidence that a ResNet34
#   nodewise or chunk arm is a 0.156-pp arm, and every scrap of evidence about the
#   arms actually being run points HIGHER.  The honest planning sd is ResNet18's
#   own FOUR-ARM pooled sd at this exact ms/alpha0/box, re-derived from the CSV:
#       nodewise   sd 0.167 (n=16)    chunk777   sd 0.216 (n=9)
#       nodewise1d sd 0.164 (n=6)     chunk2325  sd 0.123 (n=6)
#       POOLED sd = 0.1742 pp on 33 df       <-- GUARD 2g re-derives and REFUSES
#   At n=9 per arm:  se(D) = se(G) = 0.174*sqrt(2/9) = 0.082 pp.
#       D = +0.5 lands at t = 6.1 against zero.
#       vs the R18 pool, se_diff = sqrt(0.082^2 + 0.0939^2) = 0.125, so a
#       REFUTATION needs D <= +0.331 to clear |t| >= 2.  A D of +0.40 bands
#       ATTENUATED on the point estimate but is NOT separated from ResNet18
#       (t -1.45): registered in advance as CONSISTENT-WITH-R18 (UNDERPOWERED),
#       and it may NOT be written up as a refutation.
#       TOST at delta 0.30 needs |G| < 0.157 -- reachable.  At 0.15 it needs
#       |G| < 0.007 -- unreachable, which is why H2's delta is 0.30.
#       se(D-G) = 0.116 WITHIN BATCH, so R18's D-G of +0.716 would land at t 6.2.
#   **THE SPEND IS DELIBERATELY LOPSIDED TOWARD THE NULL.**  On ResNet18 the G
#   null was declared at n=3 per arm (cc1 se 0.147), which only excludes effects
#   above +-0.29.  Replicating a weak null weakly is worthless.  At n=9 the second
#   architecture carries a STRONGER mechanism test than the first.
#
# -----------------------------------------------------------------------------
# WHY ms=1e-4 IS PINNED, AND THE RULE-11 GAP THIS BATCH DOES **NOT** CLOSE
# -----------------------------------------------------------------------------
#   ms=1e-4 is chosen for TWO reasons, neither of them optimality:
#     (i)  It is the ms of the R18 anchor pool (mm1/pp1/cc1) and of the EXACT-count
#          G anchor (cc1).  H1 and H2 are read against those, so sharing the ms is
#          what makes them comparable at all.
#     (ii) It is the ONLY rung in this box that is algebraically FLOOR-FREE.  With
#          --weight-decay-meta 0 the Lion update gives |dbeta| = ms EXACTLY, so
#          over T = 100 x 500 = 50,000 updates beta can travel ms*T nats from
#          beta_0 = ln(1e-3) = -6.9078.  The floor -15 is 8.0922 nats away:
#              ms=1e-4  ms*T =  5.0 nats  -> FLOOR UNREACHABLE
#              ms=3e-4  ms*T = 15.0 nats  -> floor reachable from epoch 54.0
#                                            (and ar1 DID bind LO 12/12 there)
#              ms=1e-3  ms*T = 50.0 nats  -> floor reachable from epoch 16.2
#          GUARD 8 recomputes this and REFUSES if the emitted ms is floor-reachable.
#
#   **THE CEILING IS A DIFFERENT MATTER AND IS DISCLOSED, NOT HIDDEN.**  The
#   ceiling -2.3026 is only 4.6052 nats above beta_0, and ms*T = 5.0 > 4.6052, so
#   the CEILING is algebraically reachable from step 46,052 = epoch 92.1 -- which
#   is INSIDE the plateau5 window (epochs 96-100).  Two things make this a
#   disclosed risk rather than a defect: (a) at this exact ms and box on ResNet18,
#   rec_hi measured 0.0000 on 24/24 arms (cc1 + mm1 + pp1), so the ceiling is
#   empirically free even though it is algebraically reachable; (b) ResNet34
#   carries 25,556 coordinates against ResNet18's 14,420, i.e. ~1.8x more chances,
#   so it is NOT safe to assume.  THE SCORER THEREFORE REPORTS rec_hi PER SEED AS A
#   FIRST-CLASS NUMBER, not merely as a drop criterion, and an ARM-ASYMMETRIC
#   ceiling (|rec_hi_chunk - rec_hi_node| > 0.10) VOIDS the affected contrast.
#
#   RULE 11 IS **NOT** SATISFIED AND THE SCORER SAYS SO IN ITS OWN OUTPUT.  No
#   arm's own ms argmax is measured on ResNet34 by this batch.  The deleted g3d
#   bought a 3-rung ladder, but two of its three rungs were floor-dirty by the
#   algebra above, so the ladder could never have issued a RULE-11 certificate
#   anyway -- it would have spent 12 of 18 jobs on rungs registered in advance as
#   uninterpretable.  Those 12 jobs are not replaced; they are CUT.  The permitted
#   sentence is "D and G on ResNet34 at the R18 anchor's own ms", never "at
#   ResNet34's optimum".
#
# -----------------------------------------------------------------------------
# THE ARMS, AND WHY THESE FOUR COUNTS
# -----------------------------------------------------------------------------
#   nodewise    m = 25,556   the architecture-aligned partition (sum of shape[0])
#   chunk835    m = 25,562   count-matched to nodewise, +6 groups
#   nodewise1d  m =  8,595   the TAIL-REMOVED partition (1-D tensors get 1 group)
#   chunk2500   m =  8,587   count-matched to nodewise1d, -8 groups
#   D = chunk835 - nodewise        G = chunk2500 - nodewise1d
#
#   777 and 2325 are ResNet18/CIFAR-10 CONSTANTS and are WRONG on any other net.
#   835 and 2500 were found by binary search on the (monotone non-increasing)
#   chunk count against ResNet34's own shapes; 835 is the UNIQUE K within 8 groups
#   of nodewise, and NO K gives an exact nodewise1d match -- the chunk count skips
#   8,595 entirely.  GUARD 4 MEASURES all four m off the ALLOCATED beta on the real
#   built network and REFUSES on any mismatch; GUARD 4e cross-checks with a second,
#   torch-free instrument.
#
#   THE COUNT RESIDUAL IS HARMLESS AND IS QUANTIFIED, NOT ASSUMED.  The count slope
#   re-derived from the CSV at write time (chunk777 92.580 n=9 vs chunk2325 92.812
#   n=6 at ms=1e-4, 0.4732 decades apart) is -0.4906 pp per decade of m.  +6 groups
#   on 25,556 = 1.020e-4 decades = 5.0e-5 pp of bias; -8 on 8,595 = 4.0e-4 decades
#   = 2.0e-4 pp.  Both are 250-1,000x below the 0.05 pp resolution floor, and the
#   +6 is SMALLER than the +1-group bias ResNet18's own chunk777 already carries.
#
#   K=835 AND K=2500 ARE BOTH > 512 = the largest 1-D tensor on ResNet34, so ALL 73
#   1-D tensors get EXACTLY ONE chunk in BOTH chunk arms.  That is the property
#   that makes them the structurally identical comparators to R18's chunk777 /
#   chunk2325.  **IT IS ALSO WHY ResNet50 IS STRUCTURALLY EXCLUDED FROM THIS
#   PROGRAMME AT ANY PRICE:** its largest 1-D tensor is 2,048 and every
#   count-matching K (295, 885) is BELOW it, so a chunk arm there would SPLIT the
#   very BatchNorm tensors whose merging is the prescription.  GUARD 4 enforces
#   K > max-1-D and would refuse a ResNet50 port outright.
#
# -----------------------------------------------------------------------------
# WHAT THIS BATCH MAY **NOT** CLAIM.  Registered before any data exists.
# -----------------------------------------------------------------------------
#   * NOT a tuned-arm (RULE 11) result on ResNet34.  No argmax is measured.
#   * NOT a fifth replication of the R18 D series -- it is a DIFFERENT architecture
#     and is reported as a generalisation test, never pooled with mm1/pp1/cc1.
#   * NO FIELD STATISTIC OF ANY KIND.  PROBE=5 is exported for BOX OCCUPANCY ONLY.
#     PROBE5 is deliberately NOT exported (GUARD 1b asserts its absence), no
#     neg_counts is written, and rho_w / N_eff belong to Direction C, which was
#     DROPPED on its own pre-registered adoption gate.
#   * NOTHING about CIFAR-100 (that is `gc1`, bin/c83_gen_c100_screen.sh) and
#     NOTHING about ResNet50 (structurally excluded above).
#   * NO cross-architecture LAW.  Two architectures is two points.
#   * NO amendment to cc1's, bn1's, ar1's or fa1's own readings.
#   * T2 = nodewise1d - nodewise is COUNT-CONFOUNDED by construction (25,556 ->
#     8,595 = 0.4732 decades = +0.232 pp of pure count effect at the measured
#     slope) and is DESCRIPTIVE ONLY.  It is NOT "tail removal" and the scorer
#     refuses to label it so.
#
# STANDING RULES HONOURED: 10 (the series holds the arm fixed), 13 (every guard
# tested in BOTH directions before submission), 14 (every scored contrast is
# WITHIN this one batch, so the batch offset cancels and no floor applies), 19
# (this file and analysis/c83_gen_score.py are git-committed BEFORE any run exists).
# =============================================================================

# --- GUARD 1b -- THE ENV/ARGS PIN CHECK, against THE EMITTER REGION ONLY.

import sys
me, clip, epochs, alpha0, batch, net, dset, gamma, probe, mst = sys.argv[1:11]

BEG = "# --- EMITTER " + "BEGIN ---"

    sys.exit("GUARD FAIL: BETA_CLIP=%r is not ordered lo<hi" % clip)

# This is a CROSS-CHECK, not a gate: GUARD 4 measures m off the ALLOCATED beta on
# the real built network and is authoritative.  4e reproduces all four m from a
# torch-free shape model, so a DISAGREEMENT means the registration is wrong
# somewhere and refuses; an ABSENT census means only that the second opinion is
# unavailable, which is not a reason to block a batch guard 4 has already checked.

  python3 - "$REPO" "$NET" "$CHUNK_KD" "$CHUNK_KG" "$M_NODE" "$M_CHUNK_D" "$M_N1D" "$M_CHUNK_G" \
    <<'PYEOF' || guard_fail "guard 4e: analytic census cross-check"
import sys, os, math
repo, net, kd, kg, m_node, m_chd, m_n1d, m_chg = sys.argv[1:9]
sys.path.insert(0, os.path.join(repo, "analysis"))
import contextlib, io as _io
try:
    with contextlib.redirect_stdout(_io.StringIO()):
        import c82_singleton_census as C   # the module prints a report at import
except Exception as ex:
    print("guard 4e: cannot import the analytic census (%s) -- SECOND OPINION "
          "UNAVAILABLE, guard 4 remains authoritative" % ex)
    raise SystemExit(0)
if net not in getattr(C, "ARCHS", {}):
    print("guard 4e: the analytic census has no entry for %s -- SECOND OPINION "
          "UNAVAILABLE, guard 4 remains authoritative" % net)
    raise SystemExit(0)
blk, nb, nc = C.ARCHS[net]
# resnet_params returns (name, shape) PAIRS, not bare shapes.  Take the shapes.
shapes = [tuple(shape) for _name, shape in C.resnet_params(blk, nb, nc)]
def m_node_f(sh):   return sum(s[0] for s in sh)
def m_n1d_f(sh):    return sum(1 if len(s) == 1 else s[0] for s in sh)
def m_chunk(sh, K): return sum(int(math.ceil(math.prod(s) / float(K))) for s in sh)
vals = [("nodewise", m_node_f(shapes), int(m_node)),
        ("chunk%s" % kd, m_chunk(shapes, int(kd)), int(m_chd)),
        ("nodewise1d", m_n1d_f(shapes), int(m_n1d)),
        ("chunk%s" % kg, m_chunk(shapes, int(kg)), int(m_chg))]
for lab, got, want in vals:
    if got != want:
        sys.exit("GUARD FAIL (SECOND INSTRUMENT DISAGREES): %s gives m=%d, registered "
                 "%d.  Guard 4 and guard 4e cannot both be right -- DO NOT SUBMIT."
                 % (lab, got, want))
ones = [s for s in shapes if len(s) == 1]
sz1 = sum(s[0] for s in ones)
tot = sum(int(math.prod(s)) for s in shapes)
print("guard 4e: the torch-free census reproduces all four m independently -- %s"
      % ", ".join("%s %d" % (l, g) for l, g, _ in vals))
print("guard 4e: %d 1-D tensors, largest numel %d, %d size-1 nodewise groups = "
      "%.2f%% of m over %.4f%% of %d weights"
      % (len(ones), max(s[0] for s in ones), sz1, 100.0 * sz1 / int(m_node),
         100.0 * sz1 / tot, tot))
PYEOF

import subprocess, sys
parts, wall = sys.argv[1], sys.argv[2]
def secs(t):
    t = t.strip()
    if t in ("infinite", "UNLIMITED"): return 10**9
    d = 0
    if "-" in t: d, t = t.split("-", 1); d = int(d)
    p = [int(x) for x in t.split(":")]

# --- GUARD 7 -- THROUGHPUT HEADROOM, FROM THE ARMS THIS BATCH ACTUALLY RUNS --
# The deleted g3d measured this on ResNet18's nodewise/layerwise ratio ALONE and
# reported 1.72x.  That is not the binding arm: chunk2325 runs at 1.806x layerwise

G3M_PARTS="$PARTS" python3 - "$CSVP" "$NET" "$WALL" "$EPOCHS" "$CHUNK_KD" "$CHUNK_KG" \
  <<'PYEOF' || guard_fail "guard 7: throughput headroom"
import csv, sys, statistics as st
csvp, net, wall, epochs, kd, kg = sys.argv[1:7]
def secs(t):
    p = [int(x) for x in t.split(":")]
    return p[0] * 3600 + p[1] * 60 + p[2]
wall_min = secs(wall) / 60.0
R = list(csv.DictReader(open(csvp)))
def wc(pred):
    out = []
    for r in R:
        if not pred(r): continue
        try: out.append(float(r["wallclock_min"]))
        except Exception: pass
    return out
tgt = wc(lambda r: r["network"] == net and r["dataset"] == "CIFAR10"
         and r["epochs_done"] == epochs)
if len(tgt) < 10:
    sys.exit("GUARD FAIL: fewer than 10 %s %s-ep runs to project from" % (net, epochs))
worst = max(tgt)
# R18's MEASURED cost ratios against layerwise, for the FOUR arms submitted.
base = wc(lambda r: r["network"] == "ResNet18" and r["dataset"] == "CIFAR10"
          and r["epochs_done"] == "100" and r["granularity"] == "layerwise")
if len(base) < 20:
    sys.exit("GUARD FAIL: cannot measure the R18 layerwise reference rate")
bm = st.median(base)
ratios = {}
for gran, proxy in (("nodewise", "nodewise"), ("chunk%s" % kd, "chunk777"),
                    ("nodewise1d", "nodewise1d"), ("chunk%s" % kg, "chunk2325")):
    v = wc(lambda r, p=proxy: r["network"] == "ResNet18" and r["dataset"] == "CIFAR10"
           and r["epochs_done"] == "100" and r["granularity"] == p)
    if len(v) < 3:
        sys.exit("GUARD FAIL: no R18 cost proxy for %s (proxy %s)" % (gran, proxy))
    ratios[gran] = st.median(v) / bm
rmax = max(ratios.values())
arm = max(ratios, key=ratios.get)
proj = worst * rmax
head = wall_min / proj
print("guard 7: %s %s-ep worst wallclock %.0f min (n=%d); R18 MEASURED ratios %s"
      % (net, epochs, worst, len(tgt), {k: round(v, 3) for k, v in ratios.items()}))
print("guard 7: BINDING ARM is %s at %.3fx -> projected worst %.0f min against a "
      "%.0f min wall = %.2fx headroom" % (arm, rmax, proj, wall_min, head))
# gpu-short caps at 4:00:00.  At the binding arm's 217 min projection that is
# 1.11x -- below the floor -- and guard 6c, which reads the real caps from sinfo,
# cannot run off-cluster.  Refuse it here so a dry run catches it too.

parts = _os.environ.get("G3M_PARTS", "")
if "gpu-short" in parts:
    sys.exit("GUARD FAIL: gpu-short is in PARTS.  Its 4:00:00 cap gives %.2fx headroom "
             "on the binding arm (%.0f min projected), below the 1.40x floor.  The "
             "batch gives up gpu-short's separate GPU cap rather than risk truncation."

             "--time or drop the tightest partition.  Truncation is not cosmetic in "
             "this corpus: rs-node runs killed at epochs 24-59 FLIPPED a rung's argmax."
             % head)
PYEOF

import math, sys
clip, a0, mst, ep, spe = sys.argv[1:6]
